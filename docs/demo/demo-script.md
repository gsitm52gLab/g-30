# GS HALE 데모 시나리오와 발표 원고

제품명: **GS HALE**  
영문 정의: **Healthcare & Aesthetic Launch Enablement**  
대표 슬로건: **해외 헬스케어 진출의 모든 일**  
캠페인 메시지: **글로벌 헬스케어의 새로운 물결**

## 발표 첫 문장

> GS HALE은 해외 헬스케어 진출에 필요한 모든 일을 하나의 흐름으로 연결해, 글로벌 헬스케어 시장에 새로운 물결을 만드는 플랫폼입니다

## 현재 문서의 상태

이 문서는 최종 통합 리허설에 사용할 시나리오입니다. Supabase 전환 후보를 검증하는 동안 작성했으며, 아래 모든 동작을 최종 배포에서 수행했다는 보고가 아닙니다. 실제 시연 후보 SHA, 실행 모드, 생성한 합성 업무 ID, 실행 결과와 화면 증거는 최종 검증 패킷에 연결해야 합니다. 기본 seed의 과거 예시 업무를 새 요청·제출 흐름의 실행 증거로 사용하지 않습니다.

## 시연 준비

- [README](../../README.md)의 실행 명령을 사용합니다. 로그인부터 데이터 유지까지 보일 때는 SQLite 또는 Supabase를 선택합니다. mock은 프로세스 재시작 시 초기화됩니다.
- GSG와 브랜드는 별도 브라우저에서 합성 계정으로 로그인합니다. 서버 권한 검증과 화면 역할 전환 시연은 구분합니다.
- 합성 브랜드의 일본·리테일러 A 컨텍스트와 같은 브랜드의 리테일러 B 컨텍스트를 준비합니다. 다른 브랜드/국가의 데이터가 섞이지 않는지도 보여줍니다.
- 신규 입점 업무 한 건과 스팟 업무 한 건을 실제 요청 작성 경로로 생성합니다. 필수 줄글·숫자·파일, 선택 항목, 담당자와 기한을 포함합니다.
- 자료는 합성 상품·이미지·PDF·Excel만 사용합니다. 실제 업무 메일이나 연락처를 시연 자료로 복사하지 않습니다.
- AI는 합성 실행과 실제 OpenAI 실행을 화면 상태대로 설명합니다. 실제 호출을 보여줄 경우 저장된 실행 ID와 usage를 사용하며 발표할 때마다 새 호출을 반복할 필요는 없습니다.

| 2. 상품정보 | 독립 상품 메뉴에서 상품을 등록·수정하고 공통 정보와 컨텍스트별 코드·소비자가·자료/인증을 확인합니다. | “상품정보가 업무 안에 묻히지 않도록 독립 메뉴로 관리합니다. 브랜드 공통 정보와 거래처별 정보를 나누고, 업무에서 사용한 상품 버전은 남깁니다.” | 저장 후 새로고침 유지. 브랜드 화면에 내부 공급가나 내부 가격 열이 없음. |
| 3. 요청과 답변 | GSG가 요청을 공개하고 브랜드가 줄글과 파일을 입력해 일부 항목만 제출한 뒤 나머지를 재제출합니다. | “무슨 자료를, 누가, 언제까지 내야 하는지가 요청에 들어 있습니다. 파일 업로드와 제출은 별개이며, 일부만 준비돼도 부분 제출할 수 있습니다.” | 업로드만으로 제출/완료되지 않음. v1·v2와 작성자·파일 버전이 구별됨. |
| 4. 문의와 보완 | 해당 업무에서 질문을 보내고 GSG가 답변 또는 외부 확인 대기를 기록합니다. 공개 보완 요청에 브랜드가 반영본을 연결합니다. | “내부 메모, 실제 답변, 외부 확인 대기를 구분합니다. 보완 의견은 어떤 버전의 어느 부분을 고쳐야 하는지 연결됩니다.” | 미전송 첨부/내부 의견은 상대에게 노출되지 않음. 팝업과 상세가 같은 대화를 표시함. |
| 5. Excel과 과거 사용본 | 합성 Excel을 업로드해 열 매핑·오류·가격 권한을 미리 본 뒤 명시적으로 반영합니다. 이전 제출의 상품/파일을 다시 엽니다. | “대량 입력도 반영 전에 확인합니다. 상품을 수정해도 이미 제출한 사용본이 자동으로 바뀌지 않습니다.” | 오류 행이 있으면 전체 반영 차단. 성공 후 실제 값 일치. 이전 제출의 파일 hash와 상품 버전 유지. |
| 6. 약기법 사전검토 | 일본 일반 화장품의 일본어 POP/리플렛 합성 입력에서 읽은 범위·못 읽은 범위와 검토 결과를 확인합니다. | “AI는 약기법 검토를 돕는 한 가지 역할에 집중합니다. 원문 위치와 공식 근거, 업계 지침, 미확인 사항을 나누어 보여주며 최종 적법 판정은 하지 않습니다.” | 선택하지 않은 PDF 페이지를 읽었다고 표시하지 않음. 근거 locator·번역 검수 상태·실행/입력/corpus 버전·usage를 확인할 수 있음. |
| 7. 외부 진행과 수동 완료 | 외부 전달/실물 수령의 별도 기록을 확인하고 GSG가 미해결 항목을 보면서 수동 완료합니다. | “제출, 검토, 외부 전달, 실물 수령, 업무 완료는 서로 다른 사실입니다. 외부 대기나 AI 실패가 있어도 GSG의 판단으로 완료하고 당시 남은 내용을 보존합니다.” | 완료 시점 잔여 상태가 고정됨. 브랜드가 임의 완료할 수 없음. 프로젝트 전체가 자동 완료되지 않음. |
| 8. 유지와 추적 | 로그아웃·재로그인/다른 인스턴스에서 같은 기록을 확인하고 검색·감사 이력으로 이동합니다. | “대화를 따라 뒤로 찾던 자료를 업무와 상품의 정확한 버전에서 다시 찾습니다. 누가 언제 무엇을 바꿨는지도 함께 남습니다.” | 같은 값·버전·파일 확인. 현재 권한을 잃은 사용자는 과거 링크로도 접근할 수 없음. |

## 마무리 원고

“GS HALE은 상품정보, 요청, 제출, 문의, 보완, 외부 진행을 하나의 업무 흐름으로 연결합니다. GSG와 브랜드가 서로 무엇을 기다리는지 확인하고, 실제로 사용한 자료와 판단의 이력을 남깁니다. 해외 헬스케어 진출의 모든 일, GS HALE입니다.”

## 발표에서 구분할 사실

- 화면 동작, 실제 Supabase 저장, 실제 OpenAI 호출은 각각의 실행 증거로 설명합니다. 특정 검증의 성공을 전체 운영 검증으로 확대하지 않습니다.
- 실제 현업 Excel 호환성, 외부 이메일/운송/기관 접수, 법률 전문가 정확도 판정, 상용 백업·복구는 별도 검증 범위입니다.
- AI의 문제 후보가 0개여도 적법·승인으로 표현하지 않습니다. 한국어 번역은 기록된 검수 상태를 그대로 설명합니다.
- PC와 390px 모바일의 실제 화면 증거를 사용합니다. 녹화나 저장된 결과를 보여줄 때는 실시간 실행인 것처럼 설명하지 않습니다.
