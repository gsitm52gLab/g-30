# Shared file transfer contract (S2)

Base: accepted S1 `d09c76efaa01e53aa1137f9c8e92c5a6d2557010`. This initial contract is separate from final S2 feature acceptance. No route or feature is switched by the initial commit.

- `src/server/files/storage-runtime.ts`: `privateStorage()` is lazy, server-only, memoized after successful construction. It reads `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (legacy service-role fallback), `SUPABASE_STORAGE_BUCKET` (default `gs-hale-private`), and optional `SUPABASE_STORAGE_NAMESPACE` (default `gs-hale`). The accepted constructor validates the raw URL and namespace. Missing/invalid Storage configuration never creates a local fallback, and importing the factory does not affect SQL-only login.
- `src/server/files/contracts.ts`: `FileReadOptions.extra(s, principal, file)` is an awaited same-UoW callback returning `{authorizationStamp}`. FileService will call it with fresh original/reference authorization before and after each range and internal snapshot. The initial commit freezes this type only; FileService wiring is still pending. AI/evidence/correction/campaign/completion callbacks must verify exact parent version and inclusion, not only context membership.
- `src/features/files/transfer.ts`: `directUpload(file, {clientItemId, callbacks, state?, signal?, maximumBytes?, onProgress?})`. Callbacks are `issue(input) -> {status,capability}`, `status(id) -> GrantStatus`, `finalize(id) -> GrantStatus`, and `resolve(ready) -> featureDTO`. Features select their own currently authorized endpoints and CSRF handling. Metadata input has `clientItemId, originalName, declaredMime, expectedBytes, expectedSha256`. Keep one `UploadResumeState` object and clientItemId per selected file across retries; remove only after the user removes the item. Capabilities and TUS URLs remain in memory and are never logged or persisted as public DTOs.
- Small files use direct signed PUT; files larger than 6MiB use signed TUS with exact 6MiB chunks, authoritative HEAD on retry, and the same in-memory TUS resource. Neither path carries a service key or application cookie. Interrupted transfer does not automatically finalize incomplete bytes. An ambiguous finalize is reconciled with current status once. HTTP400/409 from signed PUT can represent an existing immutable staging object (400 independently observed in S1); they are accepted only if server finalize returns the exact verified ready record.
- `boundedDownload(metadataURL, {signal?, maximumBytes?}) -> {blob,metadata}` uses same-origin `/api/` metadata and download endpoints only. Metadata is `{id,name,mime,bytes,sha256,etag,chunkBytes,downloadUrl}` with quoted SHA256 ETag and chunkBytes=4194304. Each chunk sends exact Range and If-Match, requires 206/exact Content-Range/ETag/length, and the final Blob must match size and SHA256. A fresh ACL denial stops immediately. No signed public download URL is used. Default client maximum is64MiB; a feature may explicitly set a larger safe integer to preserve a pre-existing export limit. General uploads remain25MiB per file and AI/import consumers keep their narrower server limits.
- Cancellation stops future requests. Blob URL creation/revocation belongs to the shared view wrapper added in the full S2 wiring. The transport itself never creates object URLs or renders a file as HTML.

`npx vitest run tests/unit/storage-file-client.test.ts` covers size/hash/ETag/range mismatch, >4MiB assembly, mid-transfer revocation, external URLs, cancellation, direct uploads without server credentials, ready replay, provider400 ambiguity, interrupted TUS resume, ambiguous finalize, and lazy fail-closed configuration. These are deterministic transport checks, not actual Supabase or Vercel proof. Actual endpoint authorization, same-UoW commit/audit, full browser upload/submission and wrapper verification remain mandatory in the full S2 packet.
