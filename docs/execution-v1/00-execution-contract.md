## 현재 확인한 상태와 환경 계약

작성 시작 시 코드 없이 `.env`만 있었고, 작성 도중 사용자가 Git 초기화와 리모트 연결을 완료한 뒤 `.git`을 삭제하고 다시 초기화했다. **재초기화 이후 실제 재확인 결과** main 브랜치, 최초 커밋 전, origin이 GitHub에 연결되고 `.env`는 추적되지 않는 상태다. 이전 저장소의 식별자·커밋·연결 정보를 재사용하지 않고 매 실행 시 최신 Git 상태를 확인한다. 기존 저장소·리모트·사용자 변경을 보존하며 Git을 재초기화하거나 origin을 바꾸지 않는다. 초기 커밋이 없으면 파일 검토·비밀값 제외 후 로컬 기준 커밋을 만들어 worktree의 기준으로 사용한다. 자동 push·배포·공개는 이번 실행 범위에 포함하지 않는다.

`.env`의 `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` 설정 존재를 dotenv 파서로 확인했다. 키의 권한·결제 상태·실호출 성공은 아직 검증하지 않았다. 원본 키/전체 env를 문서·작업 패킷·프롬프트·로그에 복사하지 않는다. 서버 프로세스에서만 런타임 로드한다. 실제 확인한 endpoint는 기본 OpenAI HTTPS 주소이며 다른 업체로 우회하지 않는다.

현재 모델 표기는 `gpt-6 astra`로 공백을 포함한다. 같은 모델의 공식 API 식별자는 `gpt-6-astra`다. G00에서 모델 선택 자체는 유지하고 API 식별자만 정규화해 설정/변경 이유를 기록한다. 다른 모델로 조용히 대체하지 않는다. 근거: [OpenAI GPT-6 Astra 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra). 계정에서 실제 사용 가능한지는 G17 실호출 단계에서 별도로 검증한다.

Git 점검 때 `.env`가 최초 커밋의 스테이징에 포함되어 있어 **파일을 보존한 채 인덱스에서만 제외**하고 `.gitignore`를 추가했다. 첫 커밋·최종 커밋 전 다시 비밀값 포함 여부를 확인한다. 실데이터·원본 이메일·API 키·비공개 세션 원문은 공개 저장소에 넣지 않는다.

## 단일 Goal과 하위 체크포인트

실제 활성 Goal은 한 개다. G00~G18은 그 안의 하위 작업/완료 조건이며 19개의 활성 Goal을 동시에 생성하라는 뜻이 아니다. PRD-00~18은 같은 번호의 G00~18로 추적한다. 각 기능은 구현 후보 → 독립 검증 → 필요 시 수정 → 통합 후 회귀 → ACCEPTED를 거친다. 파일 존재나 구현자의 자기 보고만으로 다음 의존 작업을 해제하지 않는다.

범위는 컨텍스트·회원·권한, 양측 홈, 사용자에게 할당되는 신규 입점/스팟 업무, 요청·기한·줄글/파일 제출, 상품정보와 자료, 공지·문의·보완, 수동 완료, PR/실물, 일정·알림·검색·이력, 약기법 AI와 최종 검증이다. 첫 수직 흐름이 성공해도 나머지 필수 PRD를 삭제하거나 전체 완료로 바꾸지 않는다.

## 완료 판정을 세 층으로 분리

1. **제품 기능:** 합성 데이터로 모든 필수 PRD가 UI·서버·선택 DB에서 동작하며 권한/오류/복구/모바일 검증을 통과한다. mock 응답을 실제 저장·권한·AI 호출 성공으로 보고하지 않는다.
2. **연동:** 설정된 OpenAI API에 합성/허용 공개 자료로 실제 최소 호출하고 결과 schema·근거 연결·오류·usage를 검증한다. 실패 또는 미실행은 연동 미완료다. 가짜 성공으로 대체하지 않고 관련 Goal을 미완료로 유지한다.
3. **실운영 적합성:** 현업 Excel, 실제 메일 발신/수신, 실제 사용자·운영 데이터, 전문가 법률 평가와 배포 운영 검증은 확보한 자료·권한에 따라 별도로 기록한다. 이 문서의 완료 대상은 검증된 데모 제품과 명시된 연동이다. 실운영 인증·법률 적합 판정을 포함하지 않는다. 실제 메일은 앱/로컬 메일 어댑터 테스트와 별도로 미설정 상태를 남긴다.

법률 전문가 판정이나 현업 원본 미확보를 임의로 해결했다고 쓰지 않는다. 반대로 이런 자료 공백을 이유로 상품정보·업무·문의·표준 Excel 등 독립 기능 개발을 멈추지 않는다.

## 결정권과 실행 경계

일상 설계·구현·검증·수정·로컬 의존성 설치·합성 fixture·로컬 Git 커밋/통합·격리 환경은 위임 범위에서 진행한다. 설정된 OpenAI API에 한정한 합성/사용 가능한 공개 자료의 개발·검증 호출을 실행 계획에 포함한다. 프로젝트 자체 금액 상한은 없으며 기술적 timeout·동시 실행·재시도·입력 크기 제한과 사용량 관측은 유지한다. 무제한 자동 재시도나 불필요한 대량 호출을 뜻하지 않는다.

새 결제/요금제 변경, 외부 공개·배포·push, 외부 사람에게 메일 발송, 실제 업무 데이터의 외부 전송, 기존 사용자 자료 삭제·파괴적 Git 작업은 자동 수행 범위가 아니다. 해당 단계만 차단하고 독립된 나머지를 계속한다. 사용자의 추가 권한이 없으면 완료로 가장하지 않는다. 실제 운영 정책이나 법률 판단을 지어내는 것은 ‘무인 진행’에 포함되지 않는다.

- 실제 에이전트 세션 로그는 확인된 세션 ID·원본 위치·해시·접근 가능 여부를 기록한다. 비공개 원문과 제출 가능한 비식별 사본을 분리한다. 원문에 접근할 수 없으면 수집 불가로 기록하고 직접 만든 업무 로그를 원본 JSONL이라고 부르지 않는다.
- README·데모 시나리오·발표 첫 문장·최종 결과표. 앱의 일부 화면과 별도 문서만 만든 상태를 완제품으로 보고하지 않는다.

서브세션은 병렬 작업 후 요약을 메인에 반환하며, Git worktree는 Git 저장소를 전제로 하는 격리 수단이다. 이 문서의 packet·상태·검증 게이트는 GS HALE 프로젝트 운영 규약이다. 플랫폼이 자동으로 이 규칙을 보장한다고 가정하지 않는다. 참고: [OpenAI 서브세션 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents), [OpenAI worktree 문서](https://learn.chatgpt.com/docs/environments/git-worktrees).
