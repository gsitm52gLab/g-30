## 제품 목표와 적용 원칙

GSG 한국법인이 **국가 × 리테일러 × 브랜드** 컨텍스트를 만들고 사용자를 관리한다. GSG는 **신규 입점 또는 스팟 업무를 특정 사용자에게 직접 배정**하며 설명·필요 답변·참고자료·기한을 설정한다. 브랜드는 줄글·입력값·파일로 부분 답변하고 재제출한다. 상품정보는 독립적인 필수 기능이다. GSG가 보완·외부 진행을 기록하고 업무를 수동 완료한다. 이 기본 흐름을 AI보다 먼저 완성한다.

사용자의 최신 지시 → 이미 답한 결정 → 확인된 업무 원문 → 설계 기본값 → 과거 제안 순으로 충돌을 해결한다. 본문의 기본값은 구현 설계이며 승인받은 운영 정책으로 주장하지 않는다. 로그인 주체는 GSG와 브랜드다. 외부 기관은 사실 기록 대상이다. 외부 승인·보완 해소·AI 성공은 GSG 완료의 필수 조건이 아니다.

AI는 **일본 일반 화장품의 일본어 POP/리플렛 사전검토**로 제한한다. 약용/의약부외품, 범용 운영 AI, 런타임 번역은 제외한다. 실제 현업 메일·상품 기밀·개인 연락처의 외부 LLM 전송은 금지한다. 프로젝트 자체 금액 상한은 없다. $10 상한 및 $8/$9.50 경고·차단을 복원하지 않는다.

현재 대상 경로는 `/Users/evan/workspace/gs-hale`이며 제품 소스·DB·테스트가 없는 시작 상태다. 사용자에 의해 Git 초기화와 GitHub origin 연결은 완료됐고 main은 첫 커밋 전이다. 기존 Git/remote를 보존하고 최초 커밋 후 worktree 분기를 준비한다. 메인 세션은 스테이징됐던 `.env`를 인덱스에서만 제외하고 원본을 보존하며 `.gitignore`를 추가했다. 다른 `hackathon` 프로젝트의 scaffold와 과거 통과 결과는 재사용 후보일 뿐이다. 대상 프로젝트에서 검토·이식·재실행하기 전 완료 증거가 아니다. 이 문서 작성 담당은 `.env` 값을 읽거나 출력하지 않는다.

완료 기준은 화면 존재가 아니라 클릭→서버 처리→저장→다시 조회의 연결이다. 아래 `AC-모듈번호-일련번호`는 신규 수용 기준이고 `A01~A26`은 원안의 기준이다. 기존 Notion FR/BR/T와 로컬 E/R/T 번호를 혼용하지 않는다.

## PRD-00 환경과 저장구조

**목적:** 비밀키 없이 기본 업무를 재현하고, 선택 DB에서 기록이 유지되는 기반을 준비한다. **사용자 행동/화면:** 개발자는 실행 안내에 따라 mock 또는 DB 모드를 선택하고 합성 계정으로 진입한다. 운영 설정은 현재 저장 모드와 외부 연동 상태를 사실대로 표시한다.

**필드/상태:** Next.js App Router·TypeScript, 공통 저장소 인터페이스, mock fixture와 선택 SQLite/Drizzle, migration/seed를 기본 설계로 둔다. `src/app`, `features`, `domain`, `server`, `data`, `db`, `tests`, `docs`로 역할을 나눈다. Context/User/Membership, Project/Task/Assignment/RequirementSnapshot, Product/ProductVersion/ContextProduct, Submission/Answer/FileVersion, Evidence, Conversation, Correction, Review, CompletionSnapshot, Campaign, Deadline/Notification/Audit, AiRun/Source를 관계로 저장한다.

**권한/예외:** 키는 서버 환경변수에만 보관한다. `.env`는 커밋·브라우저·로그·문서에 포함하지 않는다. mock과 실제 호출, 로컬 DB와 배포 영속성을 구분한다. seed 재실행은 입력 데이터 보존/초기화 영향을 명시한다.

- **AC-00-01:** clean install 후 키 없이 mock 모드의 홈·업무·상품으로 이동한다.
- **AC-00-02:** G00 기반 완료는 DB migration/seed와 저장소 adapter로 합성 최소 레코드를 저장하고 프로세스 재시작 후 다시 읽는 것으로 검증한다. 아직 구현하지 않은 상품·문의·완료 UI나 재로그인을 G00 완료 조건으로 요구하지 않는다. 각 실제 기능의 영속성은 해당 모듈에서 검증하고 전체 사용자 여정·재로그인 영속성은 G18에서 통합 검증한다.
- **AC-00-03:** mock/DB가 같은 도메인 계약을 사용하며 화면 저장 방식 변경으로 필드 의미가 달라지지 않는다.
- **AC-00-04:** 다른 scaffold의 버전·의존성·라이선스·실행 가능 범위를 확인하고 대상 경로에서 재검증한 결과만 기록한다.
- **AC-00-05:** 기존 main/origin을 보존하고 최초 커밋에 `.env` 등 비밀파일이 포함되지 않은 것을 확인한 뒤 worktree를 생성한다.

원안 대응: A20, A25, A26.

## PRD-01 컨텍스트와 사용자

**목적:** 국가·리테일러·브랜드별로 실제 담당 사용자를 정확히 연결한다. **사용자 행동/화면:** GSG 관리자가 컨텍스트 생성→회원 생성/초대→역할·담당 범위 설정→활성화/중지/재배정을 수행한다. 공통 상단에서 현재 세 요소와 권한 있는 컨텍스트 전환을 제공한다.

**필드/상태:** 표준 Context는 countryId/retailerId/brandId 필수·조합 고유. User는 이름·이메일·신원, Membership은 contextId·역할·상태·담당 범위·초대/활성화 시각을 분리한다. 기존 이메일은 신원을 중복 생성하지 않고 멤버십만 추가한다. 상태는 초대 대기/활성/중지. 데모는 초대 링크 복사, 만료 링크와 비활성 계정 안내를 제공한다. 독립 행사는 별도 유형으로 국가·브랜드·행사명을 요구하고 리테일러 미지정임을 명시한다.

**권한/예외:** 같은 브랜드라도 다른 컨텍스트 자동 가입은 없다. 외부 기관 연락처는 계정이 아니다. 중지 시 접근을 끊고 진행 업무를 다른 활성 멤버에게 배정하되 작성자 이력을 보존한다. 독립 행사에 검토기관을 리테일러로 임의 지정하지 않는다.

- **AC-01-01:** 같은 브랜드의 다른 국가/리테일러 및 같은 리테일러의 다른 브랜드를 각각 생성하고 동일 조합 중복은 거부한다.
- **AC-01-02:** 기존 이메일을 두 컨텍스트에 연결해 신원 1개·멤버십 2개를 확인한다.
- **AC-01-03:** 중지 직후 기존 세션의 접근도 거부하며 과거 제출 작성자와 재배정 이력은 남는다.
- **AC-01-04:** 표준 컨텍스트에서 세 요소 누락을 거부하고 독립 행사 예외는 별도 유형으로 표시한다.

원안 대응: A01, A02, A19.

## PRD-02 서버 권한과 컨텍스트 격리

**목적:** 화면뿐 아니라 모든 데이터 경로에서 소속·역할·공개 범위를 강제한다. **사용자 행동/화면:** GSG 관리자는 회원/템플릿/가격 권한을 관리하고 운영자는 담당 컨텍스트를 처리한다. 브랜드 팀원은 같은 컨텍스트의 공개 업무를 조회하되 주담당자와 공동담당자만 제출·수정한다.

**필드/상태:** 세션 신원, 활성 멤버십, 역할, assignment, 공개 범위, 내부 가격 권한을 공통 정책으로 평가한다. GSG 전체 보기는 허용 컨텍스트만 합산한다. 내부 원문·메모·공급가/공급률은 별도 필드 권한이다. GSG 대리 등록은 실제 제공자와 기록자를 모두 저장한다.

**권한/예외:** 클라이언트의 contextId·role을 신뢰하지 않는다. 조회/변경·검색 개수·파일 원본/미리보기/다운로드·알림·Excel·감사·AI 입력/결과에 같은 검사를 적용한다. CSS 숨김으로 보안을 대체하지 않는다. 비공개 파일은 공개 디렉토리에 원본 이름으로 저장하지 않는다.

**단계별 검증 경계:** G02 초기 완료는 공통 권한 정책 harness와 현재 구현된 기반 API의 역할·멤버십·공개 범위 행렬로 판정한다. 아직 없는 파일·검색·알림·Excel·감사·AI API 구현을 G02의 선행 조건으로 요구하지 않는다. 이후 각 모듈은 새 조회/변경 경로와 필드/파일 접근을 권한 행렬에 추가하는 것을 자체 완료 조건으로 삼는다. 아래 전 채널 기준은 구현된 경로부터 누적 적용하며 G18에서 전 채널 회귀를 통과해야 한다.

- **AC-02-01:** 다른 컨텍스트의 ID를 읽기/쓰기 API에 넣으면 거부하고 제목·본문·개수도 노출하지 않는다.
- **AC-02-02:** 브랜드 응답/내보내기/검색에서 내부 가격·원문 필드가 제거된다.
- **AC-02-03:** 파일 URL을 아는 비회원도 원본·미리보기·다운로드에 접근할 수 없다.
- **AC-02-04:** 같은 컨텍스트의 비담당 팀원은 공개 업무 조회만 가능하고 제출 변경은 거부된다.
- **AC-02-05:** 권한 변경 후 검색·알림·AI 결과까지 새 권한이 적용된다.

원안 대응: A01, A02, A19.

## PRD-03 양측 홈과 내비게이션

**목적:** 지금 누가 무엇을 언제까지 해야 하는지 양측에서 즉시 파악한다. **사용자 행동/화면:** GSG 홈은 모든 미답변·오늘/임박/초과 마감·외부 확인 예정·새 제출·전달 필요를 담당별로 보여준다. 브랜드 홈은 사용자 할당 업무·필요 자료·기한·남은 질문·보완·GSG 담당자·공지를 보여준다.

**필드/상태:** 공통 메뉴는 홈, 신규 입점/스팟 업무, **상품정보**, 자료함/제출표, 공지/가이드, 문의, PR/행사, 일정/알림/검색, 약기법 사전검토다. GSG에는 운영 설정이 추가된다. 업무 목록/칸반과 프로젝트 타임라인은 같은 상태·담당·제품·기한 데이터로 구성한다. 내 업무/컨텍스트 전체 필터를 구분한다.

**앱 브랜딩:** 앱 헤더·로그인·브라우저 제목/메타데이터의 제품명을 GS HALE로 통일한다. 로그인에는 영문 정의와 대표 슬로건을, 홈 소개에는 대표 슬로건을 배치한다. 캠페인 메시지는 캠페인/소개 영역에 사용한다. 발표 표지에는 제품명·영문 정의·대표 슬로건, 도입 슬라이드와 발표 대본 첫 문장에는 문서 상단의 발표 문구를 그대로 적용한다. 브랜드 문구가 업무 버튼/상태 이름이나 지원 범위 설명을 대신하지 않는다.

**권한/예외:** 미답변 1개를 전체 해결로 숨기지 않는다. 권한 없음·빈 목록·검색 결과 없음·로딩·저장 실패를 구별한다. 반응형 화면에서 줄글 입력·첨부·문의가 가능해야 한다. 홈 요약과 검색은 일반 로직으로 구현한다.

- **AC-03-01:** 신규 배정 업무가 해당 브랜드 홈과 GSG 홈에 같은 담당·기한으로 나타난다.
- **AC-03-02:** 모든 주요 메뉴에서 목록→상세→관련 업무/상품으로 실제 이동한다.
- **AC-03-03:** 상품정보가 독립 메뉴로 표시되고 등록/수정 동작에 연결된다.
- **AC-03-04:** 모바일·키보드로 요청 확인→답변→첨부→문의 흐름을 완료한다.
- **AC-03-05:** 로그인·홈·앱 헤더·메타데이터와 발표 표지/도입/대본에서 지정 문구의 철자·띄어쓰기·내용이 원문과 일치한다.

원안 대응: A03, A08, A10, A18, A24.

## PRD-04 신규 입점·스팟 업무 생성과 배정

**목적:** GSG의 요청을 컨텍스트별·사용자별 실행 업무로 만든다. **사용자 행동/화면:** 신규 입점은 프로젝트에서 필요한 상품 등록·성분/인증·샘플·브랜드 소개·PR·외부 등록 작업을 선택한다. 스팟은 프로젝트 없이 추가 자료·POP·영상·문의 파생 업무를 생성한다. 정기 업데이트는 회차/대상 기간을 가진 수동 복제 업무다.

**필드/상태:** 컨텍스트·최상위 분류·제목·선택 프로젝트·GSG 책임자 1명·브랜드 주담당 1명·공동담당, 목적/줄글 설명·제작 주체·산출물·다음 행동·기한을 저장한다. 요청 항목은 짧은/긴 글·파일·선택·숫자·날짜·링크·실물, 필수/선택·조건·제품 범위·규격 출처/버전을 갖는다. 참고 양식과 제출 결과물 영역을 분리한다. 초안→공개 미리보기→요청됨→진행 중→제출됨/확인 중→보완 요청→완료에 보류/취소를 추가한다. 부분 제출·외부 대기는 별도 배지다.

**권한/예외:** 담당자는 해당 컨텍스트 활성 멤버여야 한다. 기한 미정은 허용하되 추후 확인 주체를 표시한다. 병렬 작업은 직렬 단계로 강제하지 않는다. 다중 컨텍스트 요청은 업무·담당·기한·답변을 각각 생성한다. 템플릿 변경은 영향 업무를 선택해 적용하며 기존 답변과 요청 버전을 보존한다. 추가 SKU가 기존 프로젝트를 초기화하지 않는다.

- **AC-04-01:** 병렬 신규 입점 업무와 독립 스팟 업무를 생성해 최상위 분류·담당 사용자·다음 행동이 저장된다.
- **AC-04-02:** 설명·참고 양식·제출 항목·기한을 공개하면 브랜드가 필요한 내용만 확인한다.
- **AC-04-03:** 다중 컨텍스트 생성 후 한 업무의 답변·마감 수정이 다른 업무에 영향을 주지 않는다.
- **AC-04-04:** 필수 요건 추가 시 요청 새 버전·변경 알림·추가 필요 항목이 나타나며 이전 답변은 유지된다.
- **AC-04-05:** 브랜드의 읽음·수락·일정 조정 요청이 구분되고 조정 요청만으로 마감이 변경되지 않는다.
- **AC-04-06:** 개별 업무 완료가 프로젝트 전체 완료를 자동으로 바꾸지 않는다.

원안 대응: A03, A04, A05, A14, A17.

## PRD-05 답변·파일·제출 버전

**목적:** 줄글과 파일을 같은 제출 단위로 보존하고 부분 제출·재제출을 지원한다. **사용자 행동/화면:** 담당 브랜드 사용자는 항목별 입력→임시 저장→부분/전체 제출→보완 후 재제출한다. 상품 자료를 선택해 정확한 파일 버전을 재사용한다.

**필드/상태:** Submission에 요청 버전, 항목별 답변, 줄글, 편집 원본, 확인용 PDF/이미지, 근거자료/링크, 제공자·기록자·시각을 고정한다. 업로드/임시 저장/부분 제출/전체 제출을 구분한다. 재제출은 v2/v3를 생성하고 이전 댓글·검토·전달 연결은 유지한다. 파일은 MIME/확장자·크기·해시·공개 범위·미리보기 가능 여부를 갖는다. 기본 25MiB/개·회당 10개이며 PDF, 이미지, Office, CSV, Illustrator `.ai`, ZIP, MP4/MOV를 보관한다.

**권한/예외:** 전체 제출은 형식적 충족일 뿐 승인/완료가 아니다. 큰 영상은 링크와 설명을 허용하고 가변 링크는 내용 미고정으로 표시한다. 확정 사용본은 보관 사본 또는 고정 식별자가 필요하다. ZIP/매크로 실행·외부 링크 임의 수집은 하지 않는다. 다른 컨텍스트 자료를 브랜드명만으로 자동 공개하지 않는다.

- **AC-05-01:** 필수 항목 일부만 제출해도 저장되고 남은 항목이 정확히 표시된다.
- **AC-05-02:** v2에서 줄글/파일을 바꿔도 v1의 내용·파일 참조·검토는 변하지 않는다.
- **AC-05-03:** 저장/업로드 실패와 새로고침 후 입력을 복구하며 재시도·중복 클릭으로 제출 버전이 중복 생성되지 않는다.
- **AC-05-04:** 서버가 금지 형식·크기·권한을 검사하고 실패 파일별 재시도/삭제를 제공한다.
- **AC-05-05:** 파일명 ‘최종’ 또는 업로드만으로 제출·승인·수령 상태가 변경되지 않는다.

원안 대응: A05, A06, A19, A20, A24.

## PRD-06 상품 CRUD·가격·상품 버전

**목적:** 상품을 독립 원장으로 관리하며 업무·자료·검토에 연결한다. **사용자 행동/화면:** 목록 검색/필터→등록→상세/편집→관련 업무 생성/연결→보관/판매 중단을 수행한다. 목록은 이미지·상품명·제품 코드·용량/변형·카테고리·컨텍스트 상태·부족/미확인 자료 수를 표시한다.

**필드/상태:** 최소 브랜드·상품명·제품 코드, 임시 코드 여부를 요구한다. 현지명·설명·사용법·원산지/제조정보·이미지·색상/향·용량, 전성분 원문/언어·제출일, 용기/포장/라벨/박스/ITF 정보를 관리한다. ContextProduct는 국가/리테일러·현지 SKU/JAN·등록/출시/중단·출시일 확정 수준을 저장한다. 소비자가는 통화·세금 포함 여부·적용 범위/일자를 갖고 내부 공급가/공급률은 분리한다. ProductVersion과 과거 업무의 상품 스냅샷을 둔다.

**권한/예외:** 모르는 바코드·성분 분류·만료일을 생성하지 않는다. 제품 코드 중복을 검사한다. 공통 원장 변경은 영향 컨텍스트를 알려주되 과거 스냅샷은 유지한다. 브랜드는 허용 상품·소비자가만 확인한다. 공개 협찬 비용과 내부 공급 조건을 혼동하지 않는다.

- **AC-06-01:** 등록·수정·검색·상세·업무 연결·보관이 실제 저장되고 다시 조회된다.
- **AC-06-02:** 동일 상품의 두 리테일러 SKU·상태·가격 적용 정보를 독립 관리한다.
- **AC-06-03:** 상품 수정 뒤 현재 화면은 최신값, 기존 제출/검토는 당시 스냅샷을 표시한다.
- **AC-06-04:** 브랜드의 화면/API/검색/Excel에 내부 공급가·공급률이 나타나지 않는다.
- **AC-06-05:** 보관/판매 중단 후 기존 자료·업무·작성자 이력을 조회할 수 있다.

원안 대응: A10, A11, A12, A19, A20.

## PRD-07 증빙 제출표와 Excel

**목적:** 상품별 요구 자료의 보유와 적용 확인을 분리하고 표준 일괄 등록을 제공한다. **사용자 행동/화면:** 제품×자료 표에서 각 셀의 파일 버전·요청으로 이동하고 공통 증빙을 복수 상품에 연결한다. Excel은 선택→시트/헤더→열 매핑→오류/중복/가격 권한 미리보기→명시적 반영→결과 확인으로 처리한다.

**필드/상태:** 셀은 미제출/제출됨/내용 확인 필요/적용 확인/보완 필요/해당 없음. Evidence는 문서 유형·발행/서명일·명시된 유효기간·원문 버전, EvidenceProductLink는 제품별 적용 범위와 상태를 갖는다. SDS/MSDS·질문지·보증서·갱신 청구서·제품 목록·실제 인증서를 구분한다. 가져오기는 제품 코드+컨텍스트 키, 신규/갱신/건너뛰기, batchId·출처·행 오류를 저장한다.

**권한/예외:** 질문지 서명이나 청구서가 인증 승인·현행 유효성을 확정하지 않는다. 원문 없는 만료일은 넣지 않고 확인된 기간만 갱신 알림에 사용한다. 최초 Excel은 검증 오류가 하나라도 있으면 전체 반영을 막는다. 표준 템플릿은 필수이며 미제공 현업 Excel의 매핑 검증만 별도 대기한다.

- **AC-07-01:** 공통 파일 1개를 복수 상품에 연결해 파일 버전은 공유하되 적용 확인 상태는 개별 유지한다.
- **AC-07-02:** 청구서/질문지를 연결해도 인증 승인으로 자동 변환되지 않는다.
- **AC-07-03:** 정상·오류·중복 파일에서 반영 전 미리보기와 행별 오류를 확인하고 오류 상태에서는 저장하지 않는다.
- **AC-07-04:** 브랜드 가져오기에서 내부 가격 변경을 거부하고 내보내기에도 해당 열을 포함하지 않는다.
- **AC-07-05:** 표준 가져오기 통과와 현업 양식 미검증을 서로 다른 결과로 기록한다.

원안 대응: A10, A11, A12, A19, A20, A26.

## PRD-08 공지와 가이드

**목적:** 정보 전달과 답변이 필요한 업무를 명확히 분리한다. **사용자 행동/화면:** GSG는 컨텍스트 대상 공지·FAQ·업무 유형 가이드와 양식을 작성·공개한다. 브랜드는 읽음 확인과 연결 업무 이동을 수행한다.

**필드/상태:** 대상 컨텍스트·제목·설명·가이드/양식 버전·게시/수정 시각·작성자·읽은 사용자/시각·연결 업무를 저장한다. 초안/공개/개정 상태를 구분하며 공개본 이력을 보존한다. 자료 제출·답변·기한이 필요하면 별도 요청 업무를 생성한다.

**권한/예외:** 공지 읽음은 업무 수락/제출/완료가 아니다. 공개 대상 외 컨텍스트에서 공지·첨부·읽음 명단에 접근할 수 없다. 내부 초안에는 브랜드 알림을 보내지 않는다.

- **AC-08-01:** 지정 컨텍스트에만 공지와 양식이 표시되고 읽음 사용자/시각이 저장된다.
- **AC-08-02:** 공지 읽음 후 연결 업무의 수락·제출·완료 상태는 유지된다.
- **AC-08-03:** 공지 개정 시 이전 공개본·변경 시각을 보존하며 새 공개 알림을 구분한다.

원안 대응: A04, A13, A18, A19.

## PRD-09 문의와 실시간 팝업

**목적:** 브랜드의 독립 질문과 업무별 질문을 하나의 기록에서 해결한다. **사용자 행동/화면:** 브랜드가 문의함 또는 업무 상세에서 줄글·첨부 질문을 만들고 1:1 팝업으로 대화한다. GSG는 질문별 답변·외부 확인·보완을 관리하고 필요 시 업무로 전환/연결한다.

**필드/상태:** Conversation·Question·Message에 컨텍스트, 선택 업무, 질문/답변, 공개/내부, 첨부, 작성자/시각·읽음·clientMessageId를 저장한다. 질문 상태는 GSG 답변 대기/브랜드 보완 대기/외부 확인 중/해결. 외부 대기는 상대·보낸 시각·GSG 담당·다음 확인일·최근 결과를 포함한다. 메시지는 전송 중/실패/완료를 표시한다. SSE 또는 동등 서버 이벤트와 마지막 수신 위치로 누락을 복구한다.

**권한/예외:** 접수 안내·내부 메모·확인 중은 유효 답변이 아니다. 추가 질문은 해결 이력을 남기고 재개한다. 팝업과 상세가 다른 대화 저장소를 사용하지 않는다. GSG 내부 메모는 브랜드에게 공개하지 않는다.

- **AC-09-01:** 질문 5개 중 4개 답변 후 남은 1개와 다음 확인일이 양측 화면·GSG 홈에 유지된다.
- **AC-09-02:** 팝업과 상세에서 메시지·첨부·읽음이 같은 기록으로 나타난다.
- **AC-09-03:** 연결 끊김 후 재연결하면 누락 메시지를 수신하고 재전송으로 중복 메시지가 생기지 않는다.
- **AC-09-04:** 문의를 업무로 전환해도 원 대화와 연결 이력이 유지된다.
- **AC-09-05:** 해결 후 새 질문을 등록하면 과거 해결 시각은 남고 답변 대기로 재개된다.

원안 대응: A08, A09, A18, A19, A20.

## PRD-10 수정 취합과 사람 검토

**목적:** 기관 의견을 브랜드가 실행할 수 있는 수정 묶음으로 공개한다. **사용자 행동/화면:** GSG는 내부 의견 취합→항목별 정리→브랜드 보기 미리보기→공개 묶음 전달→반영본 확인→해소 확인을 수행한다.

**필드/상태:** CorrectionItem은 출처·대상 제출 버전·페이지/위치·수정 내용/이유·공개 설명·우선순위·상태·반영 버전·해소 확인자를 갖는다. CorrectionBatch는 내부/공개, 공개 시각·작성자·대기 의견 범위를 보존한다. Review는 기관/검토자·자료 버전·매체/언어/사용처/제품 범위·수신일·결과·근거·기록자를 갖는다. 내부 검토·외부 의견·AI 후보를 구분한다.

**권한/예외:** 늦은 의견은 후속 묶음, 상충 의견은 추가 확인으로 기록한다. 긴급 부분 공개는 아직 대기 중인 기관/범위를 밝힌다. 공개본은 조용히 덮어쓰지 않는다. 브랜드 반영 제출과 GSG 해소 확인은 별도이며 새 자료 버전에 이전 승인을 자동 승계하지 않는다.

- **AC-10-01:** v1의 내부 원문은 숨기고 선별한 공개 설명만 브랜드에 노출한다.
- **AC-10-02:** v2 일부 반영 후 해당 항목만 반영 상태이며 재업로드만으로 모든 항목이 해소되지 않는다.
- **AC-10-03:** 늦은 의견·상충 의견·잘못 보낸 파일을 후속 묶음/확인 필요로 재현한다.
- **AC-10-04:** 새 버전에 과거 검토 의견을 참고 연결하되 승인 상태는 자동 승계하지 않는다.

원안 대응: A06, A07, A19.

## PRD-11 외부 진행과 GSG 수동 완료

**목적:** 외부 사실과 플랫폼 업무 종료를 정확히 구분한다. **사용자 행동/화면:** GSG는 검토 요청/신청/최종 사용 등 외부 전달을 기록하고 잔여 항목을 확인한 뒤 완료한다. 완료 후 후속 업무를 연결하거나 사유를 남겨 재개한다.

**필드/상태:** ExternalAction은 목적·대상·실제 수행자·플랫폼 기록자·자료 버전·시각·증빙·최근 진행을 저장한다. CompletionSnapshot은 현재 요청/제출/상품 버전, 미해결 항목, 외부 대기, 마지막 진행 사실, 완료자·시각·권장 메모를 고정한다. ‘GSG 업무 완료’, ‘외부 승인’, ‘게시/납품’은 독립 상태다.

**권한/예외:** 완료는 GSG만 수행한다. **외부 승인·보완 해소·전달 증빙·AI 성공 또는 메모 입력을 필수 완료 게이트로 만들지 않는다.** 기록 버튼이 실제 메일 발송/신청/게시를 실행한 것처럼 표시하지 않는다. 권한·중복·동시 수정 검사는 유지한다.

- **AC-11-01:** 미해결·외부 대기·AI 실패가 남은 업무도 GSG가 수동 완료할 수 있다.
- **AC-11-02:** 완료 시 최신 잔여 상태를 정확히 고정하고 브랜드/AI의 완료 변경은 거부한다.
- **AC-11-03:** 전달 기록을 저장해도 실제 발송·외부 승인·납품 상태가 자동 변경되지 않는다.
- **AC-11-04:** 재개/후속 업무 생성 뒤에도 기존 완료 시각·완료 당시 잔여 항목을 조회한다.
- **AC-11-05:** 동시 완료·중복 클릭은 완료 이벤트 하나만 생성한다.

원안 대응: A07, A19, A20.

## PRD-12 PR 행사와 실물

**목적:** 참여 회신·메뉴 선택·외부 신청·실물·결과 수령을 각각 추적한다. **사용자 행동/화면:** GSG는 확인한 카탈로그 메뉴/사용자 정의 요청을 공개하고 브랜드는 참여/불참/추가 협의를 회신한다. 선택 메뉴에만 준비물·일정을 생성하며 실물과 게시 URL·실행 사진·성과 리포트를 관리한다.

**필드/상태:** Campaign/MenuSelection은 메뉴명+카탈로그 버전, 원문/번역·공개 조건, 제품·수량·비용/통화/세금·취소 조건, 신청자/기록자, 참여·신청·선정·준비·진행·결과 수령을 분리한다. 기본 템플릿은 상품/서류, POP/리플렛, 브랜드페이지, 영상/교육, 행사, 샘플/배송, 정기 업데이트다. PhysicalRequirement는 목적지·용도·상품/샘플 변형·요구/발송 수량·단위·발송/도착 예정·택배사/송장·증빙·수령 확인·기록자를 갖는다.

**권한/예외:** 불참은 정상 회신으로 준비물 독촉을 중지한다. 신청 뒤 불참 요청은 자동 취소하지 않고 취소 협의로 기록한다. 촬영용과 배포용은 분리한다. 규격은 출처별 필수/권장으로 두며 영상 권장 길이를 강제 반려 조건으로 확대하지 않는다. 원문 비용·할인·포인트 충돌은 미확인으로 보존하고 과거 가격을 현재 견적으로 공개하지 않는다. ERP·자동 신청·배송 실행은 범위 밖이다.

- **AC-12-01:** 불참/미선택 메뉴에는 준비물 누락과 제출 독촉이 발생하지 않는다.
- **AC-12-02:** 참여·신청·선정·진행을 독립 변경하며 이미 신청한 불참은 취소 협의가 된다.
- **AC-12-03:** 촬영/배포 실물의 목적지·수량·발송/수령을 각각 저장한다.
- **AC-12-04:** PDF 또는 송장 등록만으로 납품/수령 완료가 되지 않는다.
- **AC-12-05:** 메뉴 번호·일정·가격의 상충 원문과 확인 상태를 함께 조회한다.

원안 대응: A04, A15, A16, A17.

## PRD-13 일정과 알림

**목적:** 내부 회신과 외부 일정을 분리하고 실제 다음 행동 담당자에게 알린다. **사용자 행동/화면:** 목록/타임라인에서 브랜드 회신·자료 제출·외부 신청·검토·보완·인쇄/발송/도착·게시/사용 일정을 추가한다. 알림 센터에서 읽음/미읽음과 관련 업무 이동을 제공한다.

**필드/상태:** Deadline은 종류·일시·시간대·확정/요청/예상/확인 필요·출처/버전·변경자·확인 주체. Notification은 이벤트·수신자·읽음·처리/실패·관련 대상이다. 공개/배정/변경은 브랜드, 제출/조정/질문은 GSG, 공개 보완/답변은 관련 브랜드에게 알린다. 기본 독촉은 달력일 D-2·당일·초과 1회/일이며 계약 SLA가 아니다.

**권한/예외:** 미정/의향/옛 메일 제목을 확정 마감으로 승격하지 않는다. 외부 대기의 다음 확인 알림은 GSG에게 보내고 브랜드 미제출 독촉으로 전환하지 않는다. 완료·취소·불참·불필요 항목은 이후 독촉 제외, 재개 시 재평가한다. 앱 알림은 기본이며 브랜드 이메일은 발신 계정/허용 수신자/정책을 설정한 뒤 별도 실제 발송 검증한다. Teams는 미확정이다.

- **AC-13-01:** 서로 다른 확정 수준·시간대·출처를 저장하고 변경 이력을 표시한다.
- **AC-13-02:** 내부 취합 중에는 알림이 없고 공개 묶음 하나에 수신자별 알림 하나가 생성된다.
- **AC-13-03:** 이벤트ID+수신자 중복 방지로 재시도에도 알림이 중복되지 않는다.
- **AC-13-04:** 종료·불참·외부 대기 사례에 잘못된 브랜드 독촉이 발생하지 않는다.
- **AC-13-05:** 실제 메일 미연동 상태를 발송 성공으로 표시하지 않는다.

원안 대응: A08, A17, A18, A26.

## PRD-14 검색·감사·동시 변경

**목적:** 권한 안에서 과거 기록을 찾고 누가 무엇을 바꿨는지 재현한다. **사용자 행동/화면:** 컨텍스트·상품/SKU·업무/문의 제목·본문·파일명·상태·담당·기간을 키워드/필터로 검색한다. 상세 이력에서 요청·배정·기한·공개·제출·보완·검토·전달·상품·완료/재개·권한 변경을 확인한다.

**필드/상태:** AuditEvent는 작성자·시각·대상/버전·변경 전후·출처·상관 이벤트ID를 보존한다. 변경 명령은 expectedVersion, 공개/제출/Excel/완료/외부 기록은 idempotencyKey와 트랜잭션을 사용한다. 충돌은 최신 내용과 재적용 안내를 제공한다.

**권한/예외:** 결과뿐 아니라 개수·정렬·페이지 이동에서도 격리한다. 최소 입점 기간 이력 보존과 과거 6개월 이상 검색 가능한 구조를 유지하며 보존/삭제 정책 확정 전 자동 삭제를 넣지 않는다. 과거 날짜 fixture는 실제 6개월 운영·백업 실적이 아니다. 검색/브리핑용 LLM을 추가하지 않는다.

- **AC-14-01:** 권한 없는 컨텍스트 키워드 검색에서 제목·본문·개수 누출이 없다.
- **AC-14-02:** 동시 수정 시 한쪽의 변경을 조용히 덮어쓰지 않고 충돌을 알린다.
- **AC-14-03:** 중요 작업 재시도 후 단일 변경/감사 이벤트가 남고 DB 재로그인 후 유지된다.
- **AC-14-04:** 6개월 이전 fixture의 업무/상품 버전과 변경자를 검색할 수 있다.

원안 대응: A19, A20, A25, A26.

## PRD-15 AI 입력·OCR·지원 범위

**목적:** 지원하는 자료만 읽고 실제 읽은 범위를 명확히 제시한다. **사용자 행동/화면:** 컨텍스트·상품·업무·제출 버전 선택→분류/매체/언어 확인→텍스트/파일·페이지 선택→전송 가능한 공개/합성 자료 확인→실행한다. 독립 검토도 권한 있는 컨텍스트에 속한다.

**필드/상태:** 일반 화장품/일본어/POP 또는 리플렛, 사용처·대상 상품/버전·입력 해시, 선택/읽은/제외 페이지, OCR 품질·미확인 구간·실패 이유를 기록한다. 기본 한도는 텍스트 10,000자, PDF 10MiB·선택 최대 10페이지, 이미지 최대 4개·합계 10MiB이며 사전 토큰 검사도 수행한다. 실행은 대기/읽는 중/분석 중/완료/실패/판단 불가로 표시한다.

**권한/예외:** 약용/의약부외품·분류 불명은 범위 밖/추가 확인으로 반환한다. 패키지·라벨·프레스릴리즈·SDS·전성분은 사람 업무로 지원하지만 AI 대상이 아니다. 일반 첨부 `.ai`는 Illustrator 파일이며 AI 입력으로 간주하지 않는다. 실제 기밀·메일·연락처는 외부 API 입력에서 제외한다.

- **AC-15-01:** 약용/분류 불명/지원 외 매체를 일반 화장품으로 추정해 실행하지 않는다.
- **AC-15-02:** PDF 일부 선택 시 선택 범위와 실제 읽은 범위만 결과에 표시한다.
- **AC-15-03:** 초과·잠금·손상·빈 파일·OCR 불명확을 명시하고 읽지 못한 구간을 검토 완료로 표시하지 않는다.
- **AC-15-04:** 공개/합성 데이터만 외부 호출에 사용하고 실제 기밀 입력은 전송하지 않는다.

원안 대응: A21, A22, A23.

## PRD-16 AI 근거·corpus·결과·사람 검토

**목적:** 법률 결론이 아닌 근거와 충돌 가능성이 있는 문제 후보를 제공한다. **사용자 행동/화면:** 사용자는 원문 위치·후보 이유·근거·미확인 범위를 확인하고 GSG는 수락/수정/기각과 사유를 기록한다. 제안이 원문을 자동 변경하거나 브랜드/외부에 자동 공개되지 않는다.

**필드/상태:** Finding은 원문 구절/위치·유형·risk·confidence·이유·추가 정보·참고 수정안. `legal_basis`는 공식 문서명·sourceId·권위 수준·exact locator·공식 URL·시행/버전일·범위, `supporting_guidance`는 보조 지침·구속력 설명을 분리한다. 근거 부족은 `human_review_required`와 이유를 기록한다. Source는 일본어 원문·사전 정렬한 한국어 비공식 번역·검수 상태·버전·stale을 저장한다. AiRun은 입력/모델/프롬프트/corpus 버전·원본 결과를 고정한다.

**권한/예외:** 후보 0개는 적법 확인이 아니다. exact locator가 없으면 만들어 채우지 않는다. 원문 개정 시 번역을 stale로 표시하고 현행 검색에서 제외한다. machine-unreviewed와 사람 검수 자료를 구분하고 기존 외부 corpus 기록을 로컬 검수 완료로 주장하지 않는다. 입력 내 지시는 자료로 취급하며 다른 컨텍스트 문안 검색을 허용하지 않는다. 런타임 번역은 없다.

탐지 ID는 YK-01 맥락/누락, 02 허위·과대 후보, 03 권위 보증, 05 분류 혼용, 06 효능 범위, 07 잔주름 조건, 09 절대/최상급, 10 이미지·후기·수치/랭킹, 11 안전성 보증, 12 성분의 제품 효능 확대, TR-01 사전 번역 정렬, EV-01 근거/평가자료 부족을 유지한다. YK-04 약용 승인 경로·YK-08 약용 승인 문구 대조는 제외한다. 이 ID는 위법 판정 코드가 아니다.

- **AC-16-01:** 정상/위험/근거 부족에서 원문 위치와 공식 근거 또는 명시적 미확인을 출력한다.
- **AC-16-02:** 법적 근거와 보조 지침, 위험 수준과 확신도를 별도 필드로 표시한다.
- **AC-16-03:** 원문 개정 뒤 stale 번역은 현행 결과에 사용되지 않는다.
- **AC-16-04:** 후보 수락/수정/기각 이력이 남고 외부 전문가 승인으로 표시되지 않는다.
- **AC-16-05:** injection·타 컨텍스트 참조 시도에도 실행 지시/권한 경계가 유지된다.
- **AC-16-06:** 입력·모델·프롬프트·corpus 버전으로 실행을 추적하며 평가셋 없이 정확도 수치를 주장하지 않는다.

원안 대응: A21, A22, A23.

## PRD-17 AI 연동·비용·오류

**목적:** 제한된 실제 연동과 비용 관측을 제공하며 AI 장애가 기본 업무를 막지 않게 한다. **사용자 행동/화면:** GSG 설정에서 AI 활성 여부와 실행 상태를 확인한다. 실행 상세에는 오류 유형·재시도 가능 여부·사용량/추정 비용을 표시한다.

**필드/상태:** 서버 SDK·환경변수 모델 설정, runId/idempotencyKey, timeout·최대 재시도·동시 실행·rate limit·입력 토큰 제한을 기술 기본값으로 정의한다. 실제 구현 시 지원 출력/이미지/PDF 경로와 모델 가격 기준일을 확인한다. 토큰·요청·실제 제공 사용량·비용 추정·오류 로그를 저장하며 확정 청구액과 구분한다.

모델의 표시명과 API 식별자를 구분한다. 기존 설정에 공백을 포함한 표시명이 있으면 실제 호출 전에 동일 모델의 공식 API ID를 확인해 정규화한다. 임의로 다른 모델로 교체하지 않으며 이 문서 작업에서 API를 호출하거나 키의 유효성을 검증하지 않는다.

**권한/예외:** 키 없음/인증·권한 오류/429/일시 서버 오류/timeout/OCR/파싱/검색 근거 부족을 구분한다. 재시도는 일시 오류에만 제한적으로 허용한다. 실패를 안전/문제없음으로 반환하지 않는다. 금액 상한은 없으며 기술 제한을 금액 차단의 대체로 사용하지 않는다. 이 문서가 OpenAI 계정 설정 변경이나 실제 호출 성공을 뜻하지 않는다.

- **AC-17-01:** 키 없음·timeout·429·파싱 오류를 주입하면 각각 명시적 실패가 표시된다.
- **AC-17-02:** 동일 실행 재시도에서 중복 작업을 방지하고 영구 오류를 무한 재시도하지 않는다.
- **AC-17-03:** AI 비활성/장애 중에도 상품·제출·문의·사람 검토·GSG 완료가 동작한다.
- **AC-17-04:** 모델/가격 기준일·토큰·비용 추정을 남기고 $10 등 프로젝트 금액 차단은 존재하지 않는다.
- **AC-17-05:** G17 ACCEPTED에는 mock/fault 검증뿐 아니라 합성 또는 사용 가능한 공개 자료를 이용한 **실제 OpenAI 호출 성공**이 필수다. 실제 응답의 schema 적합성, 입력/읽은 범위, 근거 또는 명시적 근거 부족, 모델/실행 식별자와 제공되는 usage 증거를 남긴다. mock을 실호출 증거로 대체하지 않는다. 실호출 성공과 전문가에 의한 법률 정확도 검증은 구분하며, 키/네트워크 등으로 실호출하지 못하면 G17은 미완료다.

원안 대응: A07, A22, A23, A26.

## PRD-18 최종 통합과 운영

**목적:** 모듈을 전체 사용자 여정으로 검증하고 운영 준비의 미확인을 구체적으로 남긴다. **사용자 행동/화면:** GSG 컨텍스트/회원 생성→사용자 배정→브랜드 줄글/첨부 제출→상품/증빙 연결→문의/보완→외부 기록→GSG 수동 완료를 양측 계정으로 수행한다. 신규 입점과 스팟 양쪽에서 같은 기본 규칙을 확인한다.

**필드/상태:** 검증 증거는 기준ID·실행 시각·대상 버전·저장 모드·계정 역할·절차·기대/실제 결과·증거 위치·잔여 위험을 갖는다. UI 시연·서버 권한·DB 영속성·AI 실호출·메일 실발송·현업 Excel·백업 복구를 분리한다. 로딩/빈 상태/실패/큰 파일, 레이블·키보드 포커스·모바일을 검증한다.

**권한/예외:** 실제 사용자 명단·발신 계정/허용 수신자·배포 DB/비공개 파일 저장소·악성 파일 검사·백업/복구·보존/삭제·전문가 평가·현업 양식은 확보 후 운영 검증한다. 외부 기관 계정, 전체 영업 CRM, 재고/주문/정산 ERP, 자동 신청/배송, 정기 자동 스케줄러, Teams, 카탈로그 전체 자동 변환은 기본 범위에 추가하지 않는다. 해커톤 제출 규칙은 최신 운영진 안내를 별도로 확인하며 제품 완료와 공개/제출 완료를 구분한다.

- **AC-18-01:** 두 업무 분류의 전체 여정을 GSG/브랜드 계정과 DB 모드로 재현하고 주요 기록이 재로그인 후 유지된다.
- **AC-18-02:** A01~A25의 해당 필수 기준에 결과/증거를 연결하며 G17의 실제 OpenAI 응답 검증을 포함한 모든 필수 모듈이 완료돼야 전체 완료로 표시한다. G02에서 시작한 권한 행렬을 파일·검색·알림·Excel·감사·AI까지 확장해 전 채널 회귀를 통과한다. 미구현 기준 또는 미수행 AI 실호출이 있으면 전체 완료가 아니다.
- **AC-18-03:** AI 13개 평가 관점(분류 불명·범위 밖·위치·근거/지침·locator 부족·risk/confidence·번역 정렬·stale·사람 판정/FP/FN·injection·격리·오류 미판정·버전 재현)을 실행한다.
- **AC-18-04:** 실제 OpenAI 호출은 G17 필수 완료 기준으로 검증한다. 미확보 상태에서 별도 미검증으로 남길 수 있는 운영 항목은 실제 메일, 현업 Excel 양식 적합성, 전문가 법률 평가, 운영 백업/복구이며 수행한 항목에만 성공을 기록하고 각각의 미검증 사유를 남긴다. 이 유보를 AI 실호출이나 기본 기능의 누락에 적용하지 않는다.
- **AC-18-05:** 설치/build/필수 테스트·모바일/접근성 결과와 다음 운영 설정을 인계한다.

원안 대응: A01~A26, 특히 A24, A25, A26.

## 근거 보존과 남은 자료 공백

원안의 E01~E25는 각각 PRD-01/05/10(독립 행사·버전), PRD-04/12(브랜드페이지 요청), PRD-06/07(성분·증빙), PRD-09/13(영상 부분 질문), PRD-05/10(수정 취합), PRD-06/12(샘플/포장), PRD-06/15(패키지와 AI 범위), PRD-04/11/12(제작 주체·전달), E09~E20은 PRD-06/07(상품별 SDS·인증 유형·공통 적용·요건 추가), E21~E25는 PRD-12/13(참여·메뉴·실물·일정/조건 충돌)에 반영한다. E13=SRC-015, E14=SRC-013, E15=SRC-014의 원안 매핑을 유지한다. 원안이 수행했다고 기록한 25개 파일 해시/OCR 검토를 이번 문서 작성에서 다시 수행했다고 주장하지 않는다.

과거 FR-017/028 범용 AI는 제외, FR-032/BR-028 약용 경로는 범위 밖, BR-006/025·FR-009/029·T04/05 강제 승인 조건은 PRD-11의 수동 완료로 대체한다. 나머지 원안의 FR/BR/T 요구는 위 모듈과 A 대응으로 유지한다. 원문을 재검토할 수 있도록 원안 경로와 버전을 보존한다.

현재 구현 설계를 막는 추가 사용자 결정은 없다. 미확인 사항은 현업 상품 Excel 1종과 열 의미, 실제 최종 제작 파일/영상·일부 첨부 링크, 원문의 행사 날짜/요일/메뉴/가격·할인/포인트 충돌, 실제 최종 전달·게시·수령 사실, 법률 corpus의 정확한 locator/정렬/전문가 검수, 실사용자 배정 명단, 배포 저장소/백업/보존 정책과 메일 설정이다. 이 사실들은 해당 연동·업무 생성 시 확인하며 기본 업무·상품·표준 가져오기 개발을 보류하는 이유로 사용하지 않는다.

효과 측정은 요청 후 첫 회신 시간, 마감 초과, 반복 요청, 재제출 횟수, 미해결 질문 체류 시간을 기준선부터 수집한다. 원문에 없는 절감률·정확도·성과 예측 수치를 만들지 않는다.
