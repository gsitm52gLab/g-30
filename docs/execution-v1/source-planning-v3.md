# 3. 컨텍스트, 사용자와 권한

## 3.1 운영 구조

**컨텍스트 → 사용자 멤버십 → 신규 입점 프로젝트 또는 독립 스팟 업무 → 요청 항목 → 답변/제출 버전 → 확인·보완·진행·완료 이력**으로 연결한다. 상품은 브랜드의 공통 원장을 가지되 국가·리테일러별 상품정보와 업무 연결은 해당 컨텍스트에서 관리한다.

표준 컨텍스트의 국가·리테일러·브랜드는 모두 필수이며 조합은 중복 생성하지 않는다. 예를 들어 같은 브랜드의 일본·리테일러 A와 일본·리테일러 B는 서로 다른 컨텍스트다. 같은 국가와 리테일러에 속해도 브랜드가 다르면 별도다. 화면 상단에는 항상 현재 국가 / 리테일러 / 브랜드를 표시한다. GSG 전체 보기는 권한이 있는 컨텍스트만 합산한다.

E01에는 특정 리테일러 소속이 아닌 독립 행사도 있다. 이를 특정 리테일러 입점 업무로 거짓 연결하지 않는다. **설계 기본값:** 별도 ‘독립 행사/리테일러 미지정’ 컨텍스트 유형을 두고 국가·브랜드·행사명을 필수로 받는다. 표준 리테일 컨텍스트의 3요소 필수 규칙은 그대로 유지한다. 외부 검토기관으로 CK를 기록해도 행사 소속을 CK로 바꾸지 않는다. 이 예외 유형은 원문 사례를 수용하기 위한 설계이며 실제 리테일러가 확정되면 연결 이력을 남긴다.

## 3.2 사용자 생성·초대·변경

GSG가 컨텍스트를 선택하고 이름·이메일·역할·담당 범위를 입력해 사용자를 만든다. 로그인 신원과 컨텍스트 멤버십을 분리하므로 동일인이 여러 컨텍스트에 참여할 때 계정을 중복 만들 필요가 없다. 기존 이메일이면 새 멤버십을 연결하고, 새 이메일이면 초대 대기 계정과 활성화 링크를 만든다. 초대 메일 연동 전 데모에서는 초대 링크를 복사해 활성화할 수 있다. 생성·활성화·정지·소속 변경·담당 교체를 기록한다.

사용자 비활성화 시 접근을 끊되 이전 제출·작성자 기록은 보존한다. 진행 중 담당 업무를 다른 활성 사용자에게 재배정하고 이력을 남긴다. 퇴사자를 삭제해 업무가 사라지게 하지 않는다. 동일 브랜드라는 이유만으로 모든 국가·리테일러에 자동 가입시키지 않는다. 외부 법인·검수기관 연락처를 등록하는 행동도 로그인 계정을 만들지 않는다.

**설계 기본값:** 같은 컨텍스트의 브랜드 팀원은 공개 업무를 함께 조회한다. 주담당자 1명과 선택 공동담당자가 제출·수정할 수 있으며 GSG가 담당을 변경할 수 있다. ‘내 업무’와 ‘컨텍스트 전체’를 구분한다. GSG가 브랜드 대신 자료를 기록하면 실제 제공자와 플랫폼 기록자를 둘 다 남긴다. 더 세밀한 브랜드 내부 기밀 권한은 현재 요구로 확인되지 않았으므로 복잡한 조직도를 기본으로 만들지 않는다.

권한은 화면 숨김 외에 서버 조회·변경, 검색 결과와 개수, 파일 원본/미리보기/다운로드, 알림, 내보내기, 감사 이력, AI 입력·결과까지 동일하게 검사한다. 파일 URL을 알거나 다른 ID를 입력해도 우회할 수 없어야 한다.

# 5. 업무 생성과 신규 입점 / 스팟 업무

## 5.1 두 업무 분류

**신규 입점 업무:** 특정 컨텍스트의 입점 준비를 프로젝트로 묶는다. 표준 절차에서 필요한 작업만 선택해 생성하며 상품 등록, 기본/성분 자료, 인증·SDS, 샘플/패키지, 브랜드 소개, PR 제작물, 리테일러 등록과 진행 확인을 연결한다. 동시에 진행할 수 있는 업무를 일렬 단계로 강제하지 않는다. 의존 관계가 있는 작업만 선행 작업을 표시한다. 추가 SKU는 같은 표준 절차를 재사용하되 기존 상품과 진행을 초기화하지 않는다.

**스팟성 업무:** 진행 중 추가 자료, POP/리플렛, 소개 영상, 행사 참여, 수시 확인, 납품/샘플, 문의에서 파생된 요청 등 독립 작업이다. 신규 입점 프로젝트 없이도 만들 수 있다. 월별 마케팅·정기 자료 갱신은 회차·대상 기간을 가진 스팟 업무로 템플릿 복제한다. 자동 반복 생성 스케줄러는 후속 자동화이며 수동 회차 생성은 기본 제공한다.

‘PR·행사·샘플·상품 등록’은 업무의 세부 유형이다. 최상위 분류 두 개를 이 유형들과 뒤섞지 않는다. 프로젝트와 업무의 완료도 별도이며 업무 하나의 완료로 전체 입점을 완료 처리하지 않는다.

| 항목 | 저장/동작 규칙 |

여러 컨텍스트에 같은 요청을 보내면 공통 원본과 템플릿만 재사용하고 **각 컨텍스트에 독립된 업무·담당자·마감·진행·답변**을 생성한다. 한 브랜드의 수정이 다른 브랜드 업무를 바꾸지 않는다. 동일 브랜드의 다른 리테일러에서도 자동 동기화하지 않는다.

공개 후 필수 항목·기한·설명을 수정하면 변경 내용을 알리고 요청 버전을 보존한다. 템플릿을 고쳐도 생성된 업무를 조용히 바꾸지 않는다. GSG가 영향 업무를 선택해 변경분을 적용하며 이미 받은 답변은 유지하고 새로 필요한 부분만 표시한다.

## 5.3 업무 상태와 다음 행동

설계 기본값은 **초안 → 요청됨 → 진행 중 → 제출됨/확인 중 → 보완 요청 → 완료**이며 취소·보류를 별도로 둔다. 부분 제출 상태와 외부 대기는 항목별 배지로 함께 표시한다. 이 순서는 정상 진행 예시이며 GSG의 수동 완료를 제한하는 강제 승인 체인이 아니다.

브랜드의 ‘확인’은 읽음, ‘수락/일정 조정 요청’은 작업 수락, ‘제출’은 응답 버전 확정이다. 이 셋과 GSG의 ‘완료’를 구별한다. 일정 조정 요청이 곧바로 기존 마감을 바꾸지 않으며 GSG가 반영한 결과와 이력을 남긴다. 모든 업무에서 담당·남은 항목·다음 행동·기한을 동시에 볼 수 있다.

# 6. 브랜드 답변·첨부·자료 버전

브랜드는 할당 업무에서 요청 항목별 줄글과 값을 입력하고 파일을 첨부한다. 임시 저장, 부분 제출, 전체 제출을 구분한다. 필수 항목이 남아도 부분 제출을 허용하고 미제출 목록을 정확히 표시한다. 전체 제출은 요청 항목의 형식적 충족을 확인하지만 내용 적합성이나 GSG 완료를 의미하지 않는다. 입력 내용은 실패·새로고침에 대비해 보존하고 중복 클릭으로 버전이 두 번 생기지 않게 한다.

한 제출 버전에는 텍스트 답변, 항목별 값, 편집 원본, 확인용 PDF/이미지, 근거자료와 참고 링크가 함께 들어간다. **줄글도 파일과 동일하게 제출 시점의 버전을 보존**한다. 재제출은 v2, v3로 만들고 이전 내용과 댓글·검토·전달 이력은 바꾸지 않는다. 단순 업로드나 파일명 ‘최종’만으로 제출·승인·완료를 추정하지 않는다.

기존 상품 자료를 선택하면 파일을 복제하기보다 정확한 파일 버전을 참조한다. 원래 자료의 권한과 적용 범위를 확인하고 같은 브랜드라는 이유로 다른 컨텍스트에 자동 공개하지 않는다. 공통 자료함에서 재사용할 수 있는 자료도 GSG가 공개 범위를 정한다. 상품/제출의 현재 버전이 갱신돼도 과거 업무와 검토가 가리키는 버전은 고정한다.

일반 업무의 첨부는 PDF·PNG/JPG·XLS/XLSX·CSV·DOC/DOCX·PPT/PPTX·Illustrator `.ai`·ZIP·MP4/MOV 등을 저장 대상으로 한다. 미리보기 가능 형식과 원본 다운로드 전용 형식을 표시한다. Illustrator 파일을 ‘AI 기능 입력’으로 혼동하지 않는다. ZIP 자동 실행·압축 해제, Office 매크로 실행은 하지 않는다.

**설계 기본값:** 일반 첨부 1개 25MiB, 한 번에 10개. 대용량 영상은 접근 가능한 링크와 설명을 함께 등록할 수 있다. 가변 링크만 남은 자료는 ‘외부 링크·내용 미고정’으로 표시하고 검토/사용본을 확정할 때 보관 사본이나 고정 버전 식별자를 연결한다. 외부 링크를 서버가 임의로 가져오지는 않는다. 파일 형식·크기·권한을 서버에서 검증하고 업로드 실패 시 재시도·삭제·상태를 제공한다. 실운영 저장량과 영상 업로드 확대는 실제 파일 규모를 보고 조정한다.

브랜드 공통 상품 원장과 컨텍스트별 상품 설정을 분리한다. 공통정보 변경 시 영향 컨텍스트를 보여주고 현재 화면에는 최신 정보를 표시하되, 과거 검토/제출에는 당시 스냅샷이 남는다. 브랜드는 자신에게 허용된 상품정보와 소비자가만 보고, 내부 공급가·공급률은 화면/API/Excel/검색에 모두 노출하지 않는다. GSG가 공개할 협찬 비용과 내부 공급 조건은 별도 항목이다.

## 7.2 제품×자료 제출표와 인증

행은 상품, 열은 업무에서 요청한 자료 유형으로 둔다. 미제출 / 제출됨 / 내용 확인 필요 / 적용 확인 / 보완 필요 / 해당 없음 등을 표시하며 각 칸에서 해당 버전과 요청으로 이동한다. 하나의 공통 서류가 여러 제품을 포함하면 파일은 하나로 두고 제품별 적용 관계와 확인 상태를 따로 저장한다.

SDS/MSDS, 서명된 질문지, 보증/확인서, 갱신 청구서, 제품 목록, 실제 인증서는 서로 다른 문서 유형이다. **서류가 있다는 사실을 인증 승인으로 바꾸지 않는다.** E16·E17의 서명 여부와 E19의 기간 표기는 확인할 수 있지만, 그것만으로 전체 상품의 현재 인증 유효성을 확정하지 않는다. 원문에 없는 만료일은 생성하지 않는다. 갱신 알림은 확인된 유효기간에만 적용한다.

## 7.3 Excel 가져오기와 내보내기

기본 상품 양식을 제공하고 **파일 선택 → 시트/헤더 선택 → 열 매핑 → 오류·중복·가격 권한 미리보기 → 사용자 명시적 반영 → 결과/실패 행 확인** 순서로 처리한다. 제품 코드와 컨텍스트 키로 중복을 판단하고 신규/업데이트/건너뛰기를 선택한다. 오류 행은 조용히 저장하지 않는다. 최초 버전은 검증 오류가 있으면 전체 반영을 막고 수정 후 다시 확인하는 방식으로 단순화한다. 가져오기 배치 ID와 출처를 남긴다.

실제 업무에서 사용 중인 원본 상품 Excel은 제공된 25개 파일에 없다. 따라서 **기본 상품 CRUD와 표준 템플릿 가져오기는 구현하고, 현업 Excel 한 종류와의 최종 매핑 검증은 원본 확보 후 진행**한다. 파일 미확보를 상품정보 페이지 전체의 보류 이유로 사용하지 않는다. 내보내기도 같은 필드 권한을 적용하며 브랜드 파일에 내부 가격 열을 포함하지 않는다.

# 8. 공지·가이드·문의와 실시간 대화

공지에는 대상 컨텍스트, 제목, 설명, 가이드·양식, 게시/수정 시각, 확인자·확인 시각을 둔다. FAQ와 업무 유형별 안내를 연결한다. 공지는 정보를 알리는 용도이며 답변·첨부·기한이 필요한 요청은 연결 업무를 생성한다. 공지를 읽었다는 이유로 업무를 수락·제출·완료 처리하지 않는다. 일반 공지의 확인 요청과 자료 제출 요청을 명확히 구분한다.

브랜드는 업무 상세 또는 독립 문의함에서 질문·줄글·첨부를 등록할 수 있다. GSG는 필요하면 문의를 별도 업무로 전환/연결하되 원문의 대화를 보존한다. GSG가 시작한 요청만 허용해 브랜드의 문의 통로를 없애지 않는다.

원 미팅의 **1:1 실시간 팝업 대화** 요구를 유지한다. 대화 팝업과 문의 상세는 동일한 대화·첨부·읽음 기록을 사용한다. 별도 채팅 기록으로 분산시키지 않는다. 상대가 보는 공개 대화와 GSG 내부 메모를 분리한다. 전송 중/실패/재전송, 읽음, 새 메시지를 제공하며 실시간 수신 구현 방식은 위임 설계로 SSE 또는 동등한 서버 이벤트 방식을 사용한다. 연결이 끊기면 재연결 후 누락분을 가져온다.

질문이 여러 개면 질문 항목별로 GSG 답변 대기 / 브랜드 보완 대기 / 외부 확인 중 / 해결을 관리한다. 접수 안내, 내부 메모, ‘확인 중’은 유효 답변이나 해결로 계산하지 않는다. E04처럼 5개 중 4개만 답했다면 남은 1개가 홈에 계속 보인다. 외부 대기에는 상대·보낸 시각·GSG 담당·다음 확인일·최근 결과를 기록한다. 브랜드가 추가 질문하면 해결 이력을 보존한 채 다시 답변 대기로 연다.

# 9. 수정사항 취합, 사람 검토와 수동 완료

GSG는 외부 메일/기관 의견을 내부에서 취합하고 수정항목마다 출처, 대상 제출 버전, 페이지/위치, 수정 내용, 이유, 공개 설명, 우선순위, 상태를 기록한다. 내부 원문을 그대로 브랜드에 노출하지 않는다. 브랜드 보기 미리보기 후 **공개 묶음**으로 전달하고 알림도 묶음 단위로 보낸다. 긴급 부분 공개는 아직 남은 기관 의견과 대기 범위를 명시한다.

공개한 묶음은 조용히 덮어쓰지 않는다. 뒤늦은 의견은 후속 묶음으로 추가한다. 의견끼리 충돌하면 ‘추가 확인’으로 남긴다. 브랜드의 ‘반영 제출’과 GSG의 ‘해소 확인’을 구별하며 파일을 다시 올렸다는 이유로 모든 수정항목을 해소하지 않는다. E05의 누락·잘못 보낸 파일·엠블럼 표시 문제를 재현할 수 있어야 한다.

검토는 기관/검토자, 자료 버전, 매체·언어·사용처·제품 범위, 수신일, 결과, 근거, 기록자를 갖는다. 새 버전은 이전 의견과 승인을 자동 승계하지 않는다. 내부 검토, 기관의 의견, AI 문제 후보를 별도로 표시한다. 외부 전달은 검토 요청/신청/최종 사용 등 목적, 대상, 실제 수행자, 기록자, 자료 버전, 시각, 증빙을 기록한다. 버튼으로 기록을 남겼다고 실제 메일이 발송되거나 신청·게시가 완료됐다고 표시하지 않는다.

**업무 완료의 최종 결정권은 GSG에 있다.** 완료 시 현재 요청/제출/상품 버전, 미해결 항목, 외부 대기와 마지막 진행 사실을 스냅샷으로 남긴다. 남은 항목을 한눈에 보여주되 외부 승인·전달 증빙·AI 결과·보완 해소를 필수 완료 게이트로 강제하지 않는다. 완료 메모는 권장 사항이며 새로운 복잡한 승인 절차를 만들지 않는다. 브랜드와 AI는 완료할 수 없다.

‘GSG 업무 완료’는 ‘법률 적합 확인’, ‘외부 기관 승인’, ‘실제 납품/게시 완료’와 다른 표시다. 근거가 없는 상태를 자동으로 승인/사용 가능으로 바꾸지 않는다. 완료 후 새 요청은 후속 업무를 연결하거나 GSG가 재개 사유를 남겨 다시 열며 기존 완료 시각과 잔여 항목 이력은 보존한다. 과거 BR-006/025·FR-009/029·T04/05의 강제 승인/완료 차단 조건은 이 수동 완료 결정으로 대체한다.

# 10. PR·행사 참여와 실물 업무

PR 메뉴는 상품정보 화면과 다른 **외부 리테일러의 마케팅 서비스/캠페인 요청**이다. E02의 브랜드페이지 제작 요청을 플랫폼 상품정보 페이지 대신으로 해석하지 않는다. 카탈로그 원문·번역·버전과 GSG가 확인한 공개 조건을 분리한다.

브랜드는 참여 / 불참 / 추가 협의를 회신한다. 불참은 정상적인 회신 완료로 처리하고 준비물 독촉을 중지한다. 참여 의사, 외부 신청, 심사/선정, 준비 완료, 실제 진행과 종료 후 결과 수령은 독립 상태다. 이미 신청한 건의 불참 요청은 자동 취소하지 않고 취소 협의로 기록한다. 외부 실제 신청자와 GSG 플랫폼 기록자가 다를 수 있다.

GSG는 사용할 소수 메뉴 템플릿을 선택하고 필요한 제품·수량·비용/통화/세금·취소 조건·자료/실물·신청/납품/게시 일정을 확인해 공개한다. 선택하지 않은 메뉴의 자료는 누락으로 계산하지 않는다. 메뉴 번호만으로 식별하지 않고 메뉴명과 카탈로그 버전을 함께 쓴다. 카탈로그 35쪽 전체를 자동 해석하는 엔진은 현재 필수가 아니며 사람이 확인한 템플릿과 사용자 정의 요청 항목으로 커버한다.

기본 템플릿에는 상품 등록/서류, POP·리플렛, 브랜드페이지 자료, 영상/교육, 행사 참여, 샘플·실물 배송, 정기 업데이트를 둔다. E24의 PNG·이미지 크기·문구 길이처럼 출처가 있는 규격은 해당 템플릿 버전에 넣고 모든 업무의 공통 규칙으로 확대하지 않는다. E04의 영상 권장 길이를 강제 반려 조건으로 사용하지 않는다. 제작 주체, 자막/원본 제공 책임과 사용 장소도 필요 시 요청한다.

실물 항목은 목적지·사용 목적·상품/샘플 변형·요구 수량·단위·예정 발송/도착일·발송 수량·택배사/송장·발송 증빙·수령 확인·기록자를 갖는다. 촬영용 1개와 배포용 대량 샘플은 목적지와 상태를 분리한다. PDF 제출은 샘플 납품이 아니며 송장 링크는 수령 확인이 아니다. 이 기능은 실물 업무의 기록이며 재고·배차·운송 실행·주문 ERP를 만들지는 않는다.

게시 URL·실행 사진·성과 리포트 등 후속 산출물이 요청에 있으면 별도 요구 항목과 기한을 둔다. 카탈로그의 과거 성과 수치를 우리 플랫폼의 성과 예측으로 사용하지 않는다. 메일과 PDF의 행사 날짜·메뉴 번호·가격/할인/포인트 조건이 충돌하면 둘 다 보존하고 확인 필요로 표시한다. 오래된 자료의 금액을 현재 견적으로 자동 공개하지 않는다.

# 11. 일정·알림·검색·이력

일정은 브랜드 회신, 자료 제출, 외부 신청, 검토 회신, 보완, 인쇄/발송/도착, 게시/사용 등 실제 필요한 종류만 추가한다. 날짜마다 **확정 / 요청 / 예상 / 확인 필요**, 출처와 자료 버전, 시간대, 변경자를 저장한다. 미정은 정상 마감으로 계산하지 않는다. 제출하겠다는 의향이나 메일 제목의 옛 날짜를 실제 제출·확정 마감으로 승격하지 않는다. 병렬 업무는 동시에 표시하고 선후 관계상 위험만 알린다.

통합 검색은 권한 내 컨텍스트, 상품/SKU, 업무/문의 제목·본문, 제출 파일명, 상태, 담당자, 기간을 대상으로 한다. 키워드/필터 기반으로 충분하며 검색·브리핑에 LLM을 추가하지 않는다. 정렬·페이지 이동·검색 결과 개수에도 권한을 적용한다. 목록·칸반·프로젝트 타임라인이 같은 데이터를 사용한다.

요청/템플릿 변경, 담당·기한 변경, 공개, 답변·제출, 수정 묶음, 검토, 전달, 상품 수정, 완료/재개, 권한 변경은 작성자·시각·대상 버전·변경 전후를 보존한다. ‘최소 입점 기간의 이력 보존, 과거 6개월 이상 검색 가능한 구조’라는 요구를 유지한다. 실제 보존 기간·삭제 요청 정책이 정해지기 전 자동 만료/삭제는 넣지 않는다. 데모의 과거 날짜 fixture를 실제 6개월 운영·백업 실적이라고 보고하지 않는다.

# 12. 약기법 AI 사전검토 — 지원 범위와 사용자 흐름

## 12.1 범위

**일본 일반 화장품의 일본어 POP/리플렛 문안 사전검토**만 제공한다. 사용자는 제품 분류, 사용처·매체·언어·대상 상품/제출 버전을 선택하고 텍스트·PDF·이미지를 입력한다. 분류가 의약부외품/약용화장품이거나 불명확하면 일반 화장품으로 추정하지 않고 지원 범위 밖/추가 확인 필요로 돌려보낸다.

실제 자료에는 패키지·라벨·프레스릴리즈·전성분·SDS 검토도 있다. 이 업무들은 플랫폼에서 **사람이 요청·제출·검토·기록**할 수 있어야 하지만 이번 AI 지원 범위는 아니다. 업무 생성, 요청 요약, 문의 답변, 마감/누락 판단, 수정 취합, 알림, 관리자 브리핑과 런타임 번역에는 AI를 붙이지 않는다. 계약 검토, 인증 진위 확인, 수입/통관의 법적 적합성 확정도 포함하지 않는다.

## 12.2 실행 전 확인

1. 관련 컨텍스트·상품·업무·제출 버전을 선택한다. 독립 검토도 권한 있는 컨텍스트에 속한다.
2. 일반 화장품 / 일본어 / POP 또는 리플렛인지 확인한다. 필요한 정보가 없으면 미확인을 명시한다.
3. 입력할 텍스트 또는 파일을 선택하고 실제 읽을 페이지/이미지 범위를 미리 보여준다.
4. 외부 LLM 전송 가능한 **합성 데이터 또는 사용 가능한 공개 자료**인지 확인한다. 실제 현업 메일·상품 기밀·개인 연락처는 현재 전송 허용 대상이 아니다.
5. 실행 후 진행 상태와 실패 이유를 표시하고, 완료되면 입력 스냅샷과 결과를 함께 저장한다.

AI 입력의 설계 기본값은 텍스트 10,000자, PDF 10MiB·최대 10개 선택 페이지, 이미지 최대 4개·합계 10MiB다. 모델 입력 한도에 맞춘 사전 토큰/페이지 검사도 수행한다. 초과·잠금·손상·빈 파일, 낮은 OCR 품질은 명시적으로 처리한다. 선택하지 않았거나 읽지 못한 페이지를 검토한 것으로 표시하지 않는다. 일반 업무 첨부 한도와 AI 입력 한도는 서로 다르다.

## 12.3 결과 계약

| 결과 요소 | 표시/보존 규칙 |
| --- | --- |
| 검토 범위 | 상품 분류, 매체/사용처/언어, 제출 버전, 읽은/제외한 페이지·이미지, OCR 미확인 구간 |
| 문제 후보 | 원문 구절과 위치, 문제 유형, 위험 수준과 확신도를 분리, 이유, 필요한 추가 정보 |
| 수정 제안 | 참고용 제안과 이유. 원문 자동 덮어쓰기·자동 외부 전달 없음 |
| 법적 근거 | legal_basis: 공식 문서명, source_id, 권위 수준, exact locator, 공식 URL, 시행/버전일, 적용 범위 |
| 보조 지침 | supporting_guidance: 업계 지침·해설을 법령과 구분, 구속력 설명. 리테일러 의견은 별도 |
| 판단 불가 | 정확한 근거 위치 미확인, 정보 부족, OCR 불명확, 지원 범위 밖, human_review_required |
| 재현 정보 | 입력 해시/버전, 모델·프롬프트·검색 corpus 버전, 실행 시각, 토큰/비용 추정, 원본 결과 |
| 사람 검토 | GSG가 후보 수락/수정/기각과 사유 기록. 이를 외부 전문가의 법률 승인으로 표시하지 않음 |

결과 명칭은 **‘관련 근거와 충돌 가능성이 있는 문제 후보’**다. AI는 위법/적법·승인/반려를 확정하지 않는다. 문제 후보 0개도 적법 확인이 아니다. exact locator를 찾지 못하면 조항·페이지를 만들어 채우지 않는다. 입력 안의 ‘이전 지시 무시’ 같은 문구는 자료 내용이며 실행 지시로 사용하지 않는다. 검색은 해당 상품 유형·버전·출처가 유효한 근거만 사용하고, 다른 컨텍스트의 문안을 섞지 않는다.

## 12.4 근거 자료와 검수 수준

법령·행정 문서·허용된 업계 지침을 구분하고 일본어 원문, 정확한 위치, 개정일과 출처를 보존한다. 한국어 설명은 사전에 정렬·검수한 비공식 번역을 사용한다. 런타임 번역 호출은 하지 않는다. 원문이 바뀌면 이전 번역은 stale로 표시하고 현행 근거 검색에서 제외한다. 공식 광고 규제 진입점은 [후생노동성 안내](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/iyakuhin/koukokukisei/index.html)이며 법령 원문 연결은 [e-Gov 법령 페이지](https://laws.e-gov.go.jp/law/335AC0000000145)로 관리한다. 링크가 있다는 사실만으로 전체 corpus 구축·검수가 끝난 것은 아니다.

기존 Notion 근거 목록에는 다른 환경에서 수집한 법령 자료와 번역 작업 기록이 존재한다. 이번 로컬 프로젝트에서 그 전체 원문·정렬·정확한 locator·전문가 검수 결과를 실행 검증한 것은 아니다. 따라서 현재 ‘실사용 가능한 법률 검수 corpus 완성’으로 표시하지 않는다. **데모용 machine-unreviewed 자료와 사람 검수된 자료의 상태를 분리**하고, 미검수/근거 부족 시 사람이 확인해야 함을 명시한다. 기능 데모와 법률 정확도 검증을 구별한다.

## 12.5 실패와 비용

요청 timeout, 인증/권한 오류, 429, 일시적 서버 오류, 구조화 결과 파싱 실패, 검색 근거 부족, OCR 실패를 구분한다. 재시도는 일시적 실패에 한정해 최대 횟수와 timeout을 정하고 동일 실행 요청을 중복 처리하지 않는다. 실패를 안전 판정으로 바꾸지 않는다. AI가 꺼져 있거나 실패해도 일반 업무·상품·수동 검토·GSG 완료는 동작한다.

**프로젝트 금액 상한 없음.** 과거 $10 총액, $8 경고, $9.50 차단 조건은 적용하지 않는다. 요청/토큰/비용 추정·실제 제공되는 사용량과 오류 로그는 유지한다. 비용 추정은 사용 모델과 가격 기준일을 기록하며 확정 청구액과 구별한다. 입력 크기·동시 실행·timeout·재시도·rate limit은 기술적 안정성 제한이며 금액 상한을 다시 만드는 방식으로 사용하지 않는다. OpenAI 계정 대시보드 설정을 이 문서 작업에서 실제 변경한 것은 아니다.

# 13. 구현 구조·데이터·저장·보안

Next.js App Router·TypeScript 기반으로 공통 UI와 도메인 로직을 분리한다. mock과 DB 저장소가 같은 인터페이스를 사용하도록 하며 화면은 저장 방식에 종속되지 않는다. 데모는 합성 fixture로 바로 실행되고, 선택형 SQLite 모드는 새로고침·재로그인 후 입력과 이력을 유지한다. 실제 다중 사용자 운영 시 배포 환경에 맞는 영속 DB와 파일 저장소가 필요하며 로컬 SQLite·역할 전환 버튼만으로 실운영 완료를 주장하지 않는다.

API는 컨텍스트/회원, 업무/배정/요건, 제출/파일, 상품/가져오기, 문의/메시지, 공지, 보완/검토/외부 진행/완료, 일정/알림, AI 실행 단위로 나눈다. 컨텍스트 ID를 클라이언트가 보냈다는 이유로 신뢰하지 않고 세션의 멤버십·역할을 재검증한다. 조회와 변경 모두 같은 정책을 사용한다. 내부 가격은 서버 응답에서 제거하며 클라이언트 CSS로만 숨기지 않는다.

공개·제출·Excel 반영·완료·외부 진행 기록은 트랜잭션과 멱등 키로 중복 생성에 안전해야 한다. 수정 요청은 버전 번호로 동시 변경을 검사하고 충돌 시 최신 내용과 재적용을 안내한다. 이미 다른 사람이 수정한 내용을 조용히 덮어쓰지 않는다. 완료 시 최신 상태를 읽어 정확한 스냅샷을 만들되 예전의 강제 승인 조건을 복원하지 않는다.

파일은 외부 공개 디렉토리에 원본 이름 그대로 저장하지 않는다. 비공개 식별자와 권한 확인 다운로드를 사용하고 MIME/확장자·용량을 서버에서 검사한다. 임시 업로드 정리와 파일 사용 관계를 관리한다. 배포·실운영 단계에서는 저장소 접근 제어, 악성 파일 검사, 백업/복구와 보존/삭제 정책을 검증한다. 인증 정보·OpenAI 키는 서버 환경변수에만 두며 저장소/브라우저/로그에 노출하지 않는다.

권장 디렉토리: `src/app` 라우트, `src/features` 화면/기능, `src/domain` 규칙·타입, `src/server` 인증·서비스·AI, `src/data` 저장소·fixture, `src/db` 스키마·migration, `tests` 검증, `docs` 설계. 현재 scaffold의 파일 구조와 충돌할 경우 의미 단위로 점진 정리하며 기능 변경 없이 대규모 이동부터 하지 않는다.

# 14. LLM 연동과 실운영 준비사항

현재 상세 기획을 작성하기 위해 사용자가 새로 결정해야 할 막힌 쟁점은 없다. 일반 설계는 위 기본값으로 진행한다. 아래는 **실제 연동·운영 시 확보/검증할 항목**이며 검토 전 준비 완료라고 표시하지 않는다.

| 준비 항목 | 권장안 / 담당 | 현재 판단 |
| --- | --- | --- |
| OpenAI 프로젝트·API 키 | 사용자 계정의 프로젝트 키를 서버 `.env.local`/배포 비밀값으로 설정. 채팅·Notion에 키 작성 금지 | 계정 보유 답변은 있으나 실제 호출·권한은 별도 검증 |

# 16. Goal 초안과 개발 순서

## Goal 초안 — 아직 실행 활성화하지 않음

**목표:** GSG가 국가×리테일러×브랜드별 사용자에게 신규 입점/스팟 업무를 할당하고, 브랜드가 줄글·첨부로 응답하며, 상품정보·자료·문의·기한·보완·외부 진행을 연결해 GSG가 수동 완료하는 Next.js 데모를 구현한다. 선택 DB에서 기록을 유지하고 일본 일반 화장품 POP/리플렛의 근거 기반 AI 사전검토를 독립적으로 연결한다.

**필수 산출물:** 컨텍스트/회원·권한, 양측 홈, 두 업무 분류와 생성/배정/제출, 상품 목록/상세/편집/자료 표/표준 Excel, 공지/가이드, 문의·팝업 대화, 보완 묶음, 수동 완료 이력, PR/실물 기록, 일정/알림/검색, 지원 범위가 명시된 AI 화면·오류 처리, 합성 fixture, 선택 DB migration/seed, 실행 문서와 검증 증거.

**완료 조건:** A01~A25의 해당 필수 흐름을 구현하고 UI·서버 권한·DB 영속성을 구분하여 검증한다. AI 실호출·근거 품질과 A26 외부 운영 항목은 실제 검증 상태를 표시한다. 키/외부 양식이 없어도 mock을 실호출 성공으로 보고하지 않는다. 필수 기능이 빠지면 ‘전체 Goal 완료’로 표시하지 않고 남은 범위와 진행 상태를 남긴다.

**경계:** 외부 기관 로그인, 입점 전 영업 CRM 전체, 재고/주문/정산 ERP, 외부 자동 신청/발송, 범용 AI·실시간 번역·의약부외품/패키지 전체 법률 검토, 실데이터의 외부 LLM 전송, 사용 금액 상한은 포함하지 않는다. 문서 작성은 Goal 활성화·배포·공개·제출 승인을 의미하지 않는다.

현재 단계에서 사용자에게 같은 설계 선택을 반복 질문하지 않는다. 실제 업무별 날짜·비용·담당 명단 등 사실은 해당 업무 생성 시 입력하고, 자료 없는 운영 정책을 확정 사실로 만들지 않는다. 이후 변경 요청도 새 페이지로 남기며 과거 기획을 직접 덮어쓰지 않는다.

# 18. 근거와 누락 대조표

이번 통합은 릴리스 DB의 기존 활성 페이지 **8개**를 목록 조회하고 본문을 대조했다(조회 당시 추가 페이지 없음, 보관된 페이지 0개). 여기에 원 미팅, AI 상세안, 운영/ID 대응 문서, 결정 목록과 사용자 답변을 확인했다. 로컬 검토문서 2개와 실무 폴더의 **25개 파일(24 PDF·153쪽, PPTX 1개·6슬라이드)**을 대조했다. 파일 해시는 기존 SRC 등록본과 비교했다. 문서의 수정 시각만으로 새 결정을 추정하지 않고 사용자 지시를 우선 적용했다.

텍스트형 PDF는 전 페이지 텍스트를 읽고, 이미지형 페이지는 OCR로 보완했다. 이미지 전용 PR 카탈로그 35쪽, SDS의 이미지 페이지, PPT의 12개 제품 이미지를 포함해 확인했으며 핵심 규격·일정·수량 표와 이미지도 시각 확인했다. PPT는 6개 슬라이드의 내장 이미지를 추출·확인한 것이며 원본 슬라이드 전체의 모든 작은 주석까지 읽었다고 주장하지 않는다. 메일에 언급되지만 폴더에 없는 실제 첨부/클라우드 링크의 내용을 확인했다고 간주하지 않는다.
