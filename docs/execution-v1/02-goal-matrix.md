## 공통 판정 및 실행 규약

각 체크포인트는 대응 PRD와 번호가 같다. 선행조건의 필요한 계약이 고정되면 독립 UI·fixture·검증 준비를 병렬 진행할 수 있다. 미완료 의존성이 있으면 통합 통과는 선언하지 않는다. **1 계약/합성 → 2 실제 구현/서버 → 3 DB/독립 재현** 순서로 아래 정상·실패·경계·권한·영속성 조건을 검증한다. 화면 시연은 서버 검증을, mock은 DB 영속성을 대체하지 않는다.

미실행·실패·외부 조건 대기는 통과가 아니다. 같은 실패를 반복할 때 원인과 다른 조치를 기록하며 해당 분기만 대기하고 독립 작업은 계속한다. 무인 진행은 근거 없는 자동 통과를 의미하지 않는다. 제품 안의 GSG 완료 버튼에는 이 검증 절차를 승인 게이트로 추가하지 않는다.

증거 canonical 경로는 `.execution/private/runs/<run-id>/<Gxx>/<attempt>/`다. `manifest.json`에 PRD/Goal/A 번호, revision 또는 파일 해시, 명령·환경·저장 모드·fixture 버전·시각·실행자·예상/실제 결과·판정을 기록한다. `ui/`는 화면 흐름, `api/`는 비식별 요청/응답, `db/`는 전후 조회/재시작, `independent-review.md`는 독립 재현/반례다. 아래 개별 경로는 이 기본 경로 하위의 **예정 파일**이며 현재 실행 증거가 아니다. 비밀키·개인정보·기밀은 제외한다.

독립 검증은 구현 세션과 분리된 검증 세션이 명세와 실행 방법으로 정상 및 실패/경계/권한 반례를 직접 재현한다. 분리 불가 시 자기 검증과 구별해 `독립 검증 미실행`으로 남긴다. 재현 불가, 필수 사례 누락, 명세/실행 불일치, 저장/격리 실패는 통과 불가다.
