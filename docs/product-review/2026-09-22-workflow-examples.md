# GS HALE 업무 등록·제출 흐름 재정리

2026-09-22. 사용자 피드백을 반영한 구체화 초안. 기존 PRD를 대체하거나 필수 기능을 축소하지 않는다. 아래 상품·업체·사람·날짜·파일명·답변은 모두 합성 예시다. 실제 고객 양식으로 승인받았다고 주장하지 않는다.

**최신 사용자 결정:** 업무 등록에는 별도 초안 저장·공개 단계가 필요 없다. `업무 등록` 또는 `변경 저장`을 누르면 같은 저장 처리에서 브랜드에 바로 보이도록 한다. 새 입점 프로젝트의 생성 업무와 회차 복제도 동일하다. 기존 초안을 사용자 행동 없이 일괄 공개하지 않으며, 브랜드의 답변 임시 저장·부분 제출 및 AI/문의 작성 중 상태까지 없애는 지시는 아니다. 이 변경을 양식·화면 전반 개편보다 먼저 적용한다.

## 먼저 바로잡을 문제

사용자가 확인한 문제는 화면과 동선의 복잡함, 낯선 용어, 실제 업무 등록값의 정의 부족이다.

로컬 구현에서 확인한 사실:

- 기본 양식 7개 중 대부분은 구체적인 자료 목록 없이 `요청 내용 답변`이라는 긴 글 항목 하나로 시작한다. 샘플 양식은 실물 기록, 행사 양식은 참여 관련 설명이지만 실제 메뉴별 준비물은 이 기본 양식에 정의돼 있지 않다.
- 공통 업무 편집기에 목적, 산출물, 제작 주체, 자막 책임, 원본 제공 책임, 사용 장소, 다음 행동이 함께 노출된다.
- 제출 항목마다 응답 유형, 적용 조건, 제품 범위, 규격 출처·버전 등을 바로 편집하게 한다.
- 날짜 입력에는 `날짜 정밀도`, `시간대 오프셋 포함`, `출처 버전`이 노출된다.

추가로 배포 사이트에서 합성 GSG 계정으로 로그인하고 업무 목록 → 빈 업무 등록 화면까지 실제 이동했다. 화면 전체의 노출 입력 컨트롤은 26개였고, 모바일 390px 너비에서 페이지 높이는 4,504px였다. 확인 당시 선택된 업무 대상에는 담당자·상품 선택지가 없었으며 폼은 계속 노출됐다. 다른 업무 대상도 비어 있다는 뜻은 아니다. 이 관찰에서는 업무를 생성하거나 수정하지 않았다.

배포 사이트 전체 사용성 감사나 끝까지의 업무 수행 검증은 아직 하지 않았다. 배포와 통합 브랜치의 차이는 별도로 유지한다. 관찰 원본은 비공개 `usability-review-20260922/deployed/observation.json`과 PC/모바일 스크린샷에 보존했다.

근거: `src/domain/tasks/templates.ts`, `src/features/tasks/create.tsx`, `content-editor.tsx`, `requirement-editor.tsx`, `deadline-editor.tsx`.

## 설계 기준

GSG 담당자는 업무에 맞는 양식을 골라 대상·담당자·기한·필요 자료를 확인한다. 브랜드 담당자는 요청한 자료를 입력하거나 첨부한다. 양식의 입력 방식과 조건 설정은 필요할 때 수정하는 상세 기능으로 둔다.

1. 국가·리테일러·브랜드는 현재 선택한 업무 대상을 기본으로 채운다. 등록 직전에는 세 값을 모두 확인할 수 있어야 한다.
2. GSG 담당자와 브랜드 제출 담당자는 이름으로 고른다. 동일 대상의 활성 사용자만 선택할 수 있다.
3. 제출 기한은 날짜 선택을 기본으로 하고, 시간이 필요한 때만 시간 입력을 연다. 내부에는 시간대·정확도·근거를 계속 보존한다.
4. 요청 자료는 업무 양식에 미리 들어 있어야 한다. GSG가 필수 여부·대상 상품·추가 자료를 바꿀 수 있다.
5. 제작 책임·자막·편집 원본은 관련 업무의 추가 조건에 둔다. 기존에 입력한 값은 접혀 있어도 지우지 않는다.
6. 요청 자료와 GSG가 제공하는 참고자료를 분리한다.
7. 업로드, 임시 저장, 브랜드 제출, GSG 검토, 외부 전달, 업무 완료는 서로 다른 행동으로 유지한다.
8. 고객에게 보이는 쉬운 이름을 정하되 데이터와 권한 규칙은 보존한다. 기능을 숨겨 누락된 것을 해결했다고 하지 않는다.
9. 선택한 업무 대상에 담당자가 없으면 먼저 담당자 등록·초대가 필요함을 알린다. 상품이 없으면 상품정보에서 준비할 수 있도록 안내한다. 자동으로 다른 국가·리테일러·브랜드로 바꾸거나 임의 담당자를 생성하지 않는다. 안내 링크는 실제 권한에 맞춰 제공한다.

## 예시 1 — 신규 입점 서류 요청

### 실제 자료에서 확인한 부분

보존 근거 E20 p.1–2에는 신규 입점 시 상품별 성분자료를 요청하고, 상품명이 표시된 비건 관련 자료와 PETA 관련 자료를 요청한 다음 MSDS를 추가한 흐름이 있다. 브랜드는 자료를 모아 회신했다.

이 사례가 모든 리테일러·상품의 공통 법적 요건을 뜻하지는 않는다. 요청 문서 목록은 GSG가 해당 업무에서 확정한다. 인증 자료가 첨부됐다는 사실만으로 인증의 유효성이나 적합성을 승인하지 않는다.

### GSG가 등록하는 값

| 화면 항목 | 입력 예시 | 처리 기준 |
|---|---|---|
| 업무 구분 | 신규 입점 | 기존 신규 입점 프로젝트에 연결 |
| 입점 프로젝트 | 리테일러 A 10월 신규 입점 | 해당 업무 대상의 프로젝트만 선택 |
| 업무 제목 | 입점 상품의 MSDS·인증자료 제출 | 양식에서 기본 제목 제공, 수정 가능 |
| 국가 / 리테일러 / 브랜드 | 일본 / 리테일러 A / 브랜드 라온 | 현재 선택값을 기본으로 사용 |
| GSG 담당자 | 운영 담당자 A | 현재 사용자 또는 지정 가능한 담당자 |
| 브랜드 제출 담당자 | 브랜드 담당자 B | 제출할 사용자 1명, 필요하면 공동담당 추가 |
| 대상 상품 | 데일리 크림 / 젠틀 클렌저 | 상품정보에서 선택, 상품을 새로 중복 생성하지 않음 |
| 제출 기한 | 2026-10-02 | 합성 예시 날짜. 기한 미정도 허용 |
| 요청 설명 | 선택한 상품별 MSDS와 요청한 인증 관련 자료를 제출해 주세요. | 기본 안내를 제공하고 업무별 보충 |
| 요청 자료 | 상품별 MSDS, 상품명이 표시된 비건 관련 자료, PETA 관련 자료 | 아래 자료별 적용 범위와 필수 여부 확인 |
| 참고자료 | 서류 제출 안내.pdf | GSG가 제공하는 자료, 브랜드 제출물과 구분 |

### 브랜드가 실제로 제출하는 값

| 요청 항목 | 입력 방식 | 예시 | 확인할 내용 |
|---|---|---|---|
| 상품별 MSDS | 파일, 대상 상품별 | `크림_MSDS_demo.pdf`, `클렌저_MSDS_demo.pdf` | 선택한 각 상품에 대응하는 자료인지 |
| 비건 관련 자료 | 파일 | `인증대상_상품목록_demo.pdf` | 요청 상품명이 자료에 포함되는지 사람이 확인 |
| PETA 관련 자료 | 파일 | `브랜드_증빙_demo.pdf` | 문서 종류와 요청 범위가 맞는지 사람이 확인 |
| 자료 설명 또는 미제출 사유 | 긴 글, 선택 | 클렌저 MSDS는 제조사에 요청했으며 10월 5일 보완 예정입니다. | 파일이 없다는 이유로 임시 저장·부분 제출을 막지 않음 |

위 세 종류의 자료는 이 예시 업무에서 GSG가 요청한 항목이다. 모든 업무에서 자동으로 필수 처리하지 않는다. 여러 상품에 해당하는 공통 문서는 하나의 정확한 파일 버전을 연결해 재사용하며, 적용 상품을 별도로 확인한다.

### 부분 제출과 검토 예시

1. 브랜드가 크림 MSDS와 공통 자료를 제출하고 클렌저 MSDS는 비워 둔다.
2. `가능한 자료 먼저 제출` 후에는 제출한 자료와 `클렌저 MSDS 미제출`이 함께 표시된다.
3. GSG는 클렌저 자료 보완을 요청한다. 기존 자료가 모두 승인됐다는 의미로 처리하지 않는다.
4. 브랜드가 클렌저 MSDS를 추가해 다시 제출한다. 이전 제출·파일·검토 기록은 유지한다.
5. GSG는 자료별 검토를 기록한다. 외부 전달은 별도로 기록한다.
6. 업무 완료는 GSG가 결정한다. 남은 확인사항이 있으면 완료 시점의 잔여 내용으로 보존한다.

## 예시 2 — 브랜드 페이지 제작 자료 요청

### 실제 자료에서 확인한 부분

보존 근거 E02 p.2–5에는 카테고리 순서, 수정한 소개 문구, 배경색 코드, 문구에 대한 증빙, 주석 보완 요청이 있다. 배경색은 여러 영역별 색상이 아니라 한 가지 색상을 지정하는 것으로 회신됐다. p.1은 외부 제출 완료·페이지 반영 예정이며 게시 완료 증거는 아니다.

이 예시는 선택된 PR 메뉴의 자료 제출을 독립 스팟 업무로 구체화한 설계다. 원본에 완성된 플랫폼 입력 양식이 있었던 것은 아니다. 이미지 규격·글자 수는 확인된 안내 버전이 있을 때만 적용하며, 이 메일만으로 새로운 제한을 만들지 않는다.

### GSG가 등록하는 값

| 화면 항목 | 입력 예시 | 처리 기준 |
|---|---|---|
| 업무 구분 | 스팟 업무 | 신규 입점 프로젝트 없이 등록 가능 |
| 업무 제목 | 브랜드 페이지 제작 자료 제출 | 업무 양식 기본값 |
| 국가 / 리테일러 / 브랜드 | 일본 / 리테일러 A / 브랜드 라온 | 기존 업무 대상 사용 |
| 브랜드 제출 담당자 | 브랜드 담당자 B | 사용자 배정 |
| 제출 기한 | 2026-10-07 | 합성 예시, 실제 기한으로 오해하지 않도록 표시 |
| 요청 설명 | 카테고리 순서·일본어 소개 문구·배경색 한 가지·문구 근거자료를 제출해 주세요. | 제출물을 명시 |
| 참고자료 | 페이지 제작 안내_demo.pdf | 적용할 양식·검토 의견의 버전 연결 |
| 외부 게시 희망일 | 필요할 때 추가 | 브랜드 제출 기한과 구분, 미확정이면 그 상태 유지 |

### 브랜드가 실제로 제출하는 값

| 요청 항목 | 입력 방식 | 합성 예시 | 형식·검토 기준 |
|---|---|---|---|
| 카테고리와 표시 순서 | 여러 줄 텍스트 | `1. 클렌징` / `2. 크림` | 현재 허용 카테고리 목록이 없으므로 임의의 확정 선택지를 만들지 않음 |
| 일본어 브랜드 소개 문구 | 긴 글 | `毎日のスキンケアに寄り添うブランドです。` | 문구 저장·버전 보존. 적법성을 자동 승인하지 않음 |
| 배경색 | 짧은 글 | `#E8EEF4` | 색상 한 가지. 초기 안내는 `#`와 영문·숫자 6자리로 제안, 자동 검사 구현 전에는 자동 검사됐다고 표시하지 않음 |
| 소개 문구의 근거자료 | 파일, 업무별 필수 여부 확인 | `표현_근거자료_demo.pdf` | 어떤 표현을 뒷받침하는지 함께 확인 |
| 근거자료 설명·주석 | 긴 글, 업무별 필수 여부 확인 | 요청한 표현을 삭제했고 수정 문구를 반영했습니다. | 근거 제출 또는 표현 수정의 실제 처리 기록 |

브랜드 로고와 메인 이미지는 해당 안내에서 요청될 때 추가한다. 파일에 실제로 없는 외부 양식이나 상품 Excel을 이미 확보한 것처럼 취급하지 않는다.

### 제출과 외부 진행 예시

1. 브랜드가 네 가지 핵심 자료와 필요한 설명을 입력하고 제출한다.
2. GSG는 수정할 문구를 지정해 보완을 요청한다. 브랜드는 새 제출 버전으로 회신한다.
3. GSG가 외부에 전달한 사실을 기록한다. 이때 브랜드 입력값을 바꾸지 않는다.
4. 외부 제출 완료와 페이지 반영 예정이 표시된다. 실제 게시 확인 전에는 게시 완료로 바뀌지 않는다.

| 필요한 산출물 | 제출받을 자료 | 요청 항목과 실제 제출물의 연결 |
| 응답 유형 | 입력 방식 | 글·파일·선택·숫자 등 형식 |
| 적용 조건 | 이 항목을 받는 경우 | 조건부 필수 항목과 기존 답변 보존 |
| 규격 강도 | 반드시 지킬 조건 / 권장사항 | 자동 반려 여부와 사람 검토 구분 |
| 날짜 정밀도 | 시간까지 지정 | 내부 날짜/일시·시간대 보존 |
| 확정 수준 | 일정 상태 | 확정 / 요청 중 / 예상 / 확인 필요 |
| 초안 저장 후 별도 공개 | 업무 등록 / 변경 저장 | 저장 성공 시 요청 버전까지 원자적으로 반영하고 브랜드에 표시 |
| 부분 제출 | 가능한 자료 먼저 제출 | 미제출 항목과 이전 제출 유지 |
| 전체 제출 | 요청 자료 제출 | 제출이 검토 완료나 업무 완료를 뜻하지 않음 |

첫 화면에는 업무 대상, 업무 양식, 담당자, 제출 기한, 제출받을 자료가 먼저 보인다. 요청 항목의 조건·규격 편집, 제작 세부 책임, 외부 일정, 다른 대상에 복제는 필요할 때 펼친다. 상세 기능을 닫아도 기존 값은 유지한다.

## 구현·검증 조건

기존 PRD-03/04/05/06/07/10/11/12의 조건을 유지하며 아래를 추가 확인한다.

- UXR-01: 두 기본 양식을 고르면 위 사례에 맞는 이름 붙은 제출 항목이 실제로 채워진다. 하나의 범용 답변칸으로 대체하지 않는다.
- UXR-02: 빈 업무에서 GSG가 제출 항목의 형식·조건을 새로 설계하지 않고 대상·담당·기한을 정해 요청을 보낼 수 있다.
- UXR-03: 기존 기본 양식의 내용을 덮어쓰지 않는다. 새 양식 버전으로 제공하고 이전 요청·제출·참조는 유지한다.
- UXR-04: 브랜드가 무엇을 제출해야 하는지, 이미 제출한 것과 남은 것을 같은 업무에서 확인한다. 부분 제출·재제출 결과를 실제 저장 후 다시 확인한다.
- UXR-05: 상품별 MSDS와 공통 증빙의 적용 범위를 혼동하지 않는다. 다른 업무 대상 자료는 재사용 후보에 나타나지 않고 서버도 접근을 거부한다.
- UXR-06: GSG 검토와 브랜드 제출, 외부 전달·게시, GSG 수동 완료가 별도로 기록된다.
- UXR-07: 기본 흐름에 날짜 오프셋 문자열·내부 식별자·규격 버전을 직접 입력할 필요가 없다. 추가 설정과 기존 기록은 접근 가능하다.
- UXR-08: PC와 모바일에서 GSG 요청 → 브랜드 부분 제출 → 보완 후 재제출 → GSG 확인을 새 합성 데이터로 실행한다. 클릭 경로·저장값·대기시간·오류를 기록하고 기존 보안 회귀를 통과한다.
- UXR-09: 사용자가 실제로 이해할 수 있다는 최종 판단을 자동 테스트 통과만으로 대신하지 않는다. 고객 사용성 검토는 별도 미검증으로 남긴다.
- UXR-10: 업무 등록·변경 저장·새 프로젝트의 업무 생성·회차 복제 후 브랜드가 곧바로 조회한다. 필수값 오류 시 중간 초안이나 일부 요청을 남기지 않으며, 재시도로 중복 생성하지 않는다. 기존 요청·제출 이력과 내부 메모 비공개를 보존한다.
